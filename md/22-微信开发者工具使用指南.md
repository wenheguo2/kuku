## 〇、全量启动流程（每次改代码后必须执行）

> **铁律：改了代码就必须重新编译前端，如果改了后端就重启后端 + 确认后端服务在跑。不能只编译前端不管后端。**

```powershell

# === 第 2 步：编译前端 ===

# 编译产物在 miniapp/dist/

# === 第 3 步：重载微信开发者工具（必须用脚本，光点"编译"可能连旧实例看不到变化） ===
node scripts\ide-launch.cjs

# === 第 4 步：截图验证改动真实生效（交付前必做） ===
```

### 关键配置文件

**`miniapp/.env`**（必须存在，否则编译默认走 mock 数据导致封面全白）：
```env
TARO_APP_USE_MOCK=false
TARO_APP_API_BASE_URL=http://localhost:3000/api/v1
TARO_APP_STATIC_BASE_URL=http://localhost:3000/static
```

**`server/.env`**（已存在，一般不需要改）：
- `PORT=3000`
- `STATIC_ROOT=../production`（静态图片/索引来源）

### 故障排查速查表

| 现象 | 原因 | 解决 |
|:--|:--|:--|
| 封面/图片全白 | 后端服务没跑 或 USE_MOCK=true | 确认 `localhost:3000` 可访问；检查 .env |
| 数据加载失败 | 后端服务崩了 | 杀进程重启：`Stop-Process -Name node -Force; cd server; node dist/main.js` |
| 页面空白/wxml not found | 微信工具打开了 miniapp/ 而不是 miniapp/dist/ | 关闭重新导入，选 dist 目录 |
| 编译后无变化 | IDE 缓存旧产物 | 点“编译”或用 `ide-launch.cjs` 重载 |
| 播放器无声/报错 | 音频文件在 production/ 下，需服务端 /static 可达 | 同“封面全白”处理 |

### 重启后端的正确姿势

```powershell
# 找到占用 3000 端口的进程并杀掉
netstat -ano | Select-String ":3000 .*LISTENING"
Stop-Process -Id <PID> -Force

# 从 server 目录重新启动（必须在 server/ 下执行，否则 STATIC_ROOT 路径解析错）
cd d:\work\work\code\testsuit\公司\项目\酷酷儿童故事\server
node dist/main.js
```

## 二、两条铁律

**1. 项目目录必须选 `miniapp\dist`，不是 `miniapp`**
`dist/project.config.json` 里 `miniprogramRoot` 已处理好。选错会报 `pages/xxx.wxml not found` + 整页空白。
手动导入时同样选 `dist`，AppID 选"游客模式"。

**2. 重载用 `close --project`，不要用 `quit`**
`quit` 不会真正结束 IDE 进程（服务端口仍在监听），之后 `auto` 只是**连回旧实例、旧编译产物**。
症状很坑：**automator 能 `connect` 成功，但 `currentPage`/`screenshot` 全部 `timeout waiting for automator response`**，
console 伴随 `routeDone with a webviewId N is not found`。此时反复重启无用，会白费很多时间。
`scripts\ide-launch.cjs` 已按 `close --project` → `auto --project` 实现，直接用它即可，**不需要手动点【编译】**。

**★铁律三：改完代码看不到变化时，按下面顺序排查（2026-07-30 实战复盘）**
1. `taro build` 成功时**只打印一行 banner，无任何"编译完成"字样**（兼容 Node24 删了 webpackbar 进度条）——判断构建是否生效看 `dist/common.js` 的修改时间是否刷新：
   `Get-Item dist\common.js | Select LastWriteTime`
2. dist 更新了但模拟器还是旧画面 → IDE 没重载，跑 `node scripts\ide-launch.cjs`（必须，不能只点编译）
3. 验证 dist 内容时**不要直接搜中文**（webpack 会转义成 `\uXXXX` 搜不到造成误判），搜 ASCII 标识（如资产名 `icon_friend_test`）
4. 前端数据不对 → 查后端服务是否在跑（`curl localhost:3000/api/v1/health`），挂了则按〈〇节〉重启

## 三、CLI 原理（脚本内部做的事，一般不用手敲）

PowerShell 里**不能直接跑 `cli.bat`**（会 `Maximum setlocal recursion level reached` 爆栈），
也不能 `node cli.js`（它按 CWD 找内部模块，报 MODULE_NOT_FOUND）。
正确姿势是用 IDE 自带 Electron 以 Node 模式跑内部 CLI：

```powershell
$env:ELECTRON_RUN_AS_NODE='1'; $env:cwd=(Get-Location).Path
$boot="const e=process.argv[1],a=process.argv.slice(2).filter(function(x){return x!=='--electron'});if(!process.env.cwd)process.env.cwd=process.cwd();process.argv=[process.execPath,'--ms-enable-electron-run-as-node',e,'--electron'].concat(a);require(e)"
& "D:\soft\微信助手\微信web开发者工具\微信开发者工具.exe" -e $boot `
  "D:\soft\微信助手\微信web开发者工具\resources\app.asar.unpacked\js\common\cli\index.js" `
  auto --project "…\miniapp\dist" --auto-port 9423
```

子命令：`auto`（开项目+自动化端口）、`close --project X`（关项目窗口）、`quit`（关工具）。
若必须用 cmd 窗口，可直接 `"…\cli.bat" open --project "…\miniapp\dist"`（cmd 下不递归）。

## 四、automator 脚本写法

```js
const automator = require('miniprogram-automator');
// ★必需：跳过版本检查，否则报 Cannot read properties of undefined (reading 'split')
const MPmod = require('miniprogram-automator/out/MiniProgram');
(MPmod.default || MPmod).prototype.checkVersion = async () => {};

const mini = await automator.connect({ wsEndpoint: 'ws://localhost:9423' });
// 启动后页面栈可能为空 → reLaunch 兜底
try { await mini.reLaunch('/pages/story/index/index'); }
catch (e) { await mini.evaluate(() => { wx.reLaunch({ url: '/pages/story/index/index' }); }); }
```

注意：
- 用 `connect` 不用 `automator.launch`（launch 需 cliPath，实测报 "please make sure cliPath is correctly specified"）
- **少用 `reLaunch`**：一个脚本里连续几十次 reLaunch 会把 IDE 路由搞乱导致全超时；优先 `switchTab` / `navigateTo` / 元素 `tap()`
- 原生弹窗（`showModal`/`showActionSheet`）自动化点不到，只能验证入口，实际操作需真机手点
- PowerShell 会吞 `$(...)`，automator 逻辑一律写成 `.cjs` 文件再执行，不要用 `node -e`

### 2️⃣ 后端部署（云服务器）

```bash
# 1. 拉代码
git clone <仓库> && cd server

# 2. 装依赖
npm ci --production

# 3. 编译
npm run build

# 4. 配置环境变量（复制模板并填写真实值）
cp .env.example .env
# 必改项：
#   NODE_ENV=production
#   RELEASE_MODE=true
#   PORT=3000
#   DB_HOST / DB_PORT / DB_NAME / DB_USER / DB_PASSWORD  → 真实 PostgreSQL
#   REDIS_HOST / REDIS_PORT  → 真实 Redis
#   JWT_SECRET  → 随机强密钥（≥ 32 位）
#   WX_LOGIN_MODE=real
#   WX_APPID / WX_SECRET  → 真实值
#   WXPAY_MCH_ID / WXPAY_API_V3_KEY  → 真实值（有支付时）
#   ALLOW_MOCK_LOGIN=false
#   ALLOW_PAYMENT_STUB=false
#   ADMIN_PASSWORD_SCRYPT=scrypt$<saltHex>$<hashHex>  → 生成命令见 admin/README.md
#   ADMIN_JWT_SECRET  → ≥ 32 位随机值
#   USER_AGREEMENT_VERSION / PRIVACY_VERSION / CHILDREN_PRIVACY_VERSION  → 正式版本号
#   STATIC_ROOT  → 生产不需要（图片走 CDN），或指向上传后的本地副本

# 5. 初始化数据库（TypeORM synchronize 在生产应关闭，用 migration）
# 开发期先用 synchronize=true 起表，后续切 migration

# 6. 启动（用 pm2 守护）
npm install -g pm2
pm2 start dist/main.js --name kuku-server
pm2 save && pm2 startup
```
