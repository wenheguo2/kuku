# 22 - 微信开发者工具使用指南

> **目标读者**：前端 / 测试 / 自动化脚本维护者
> **文档作用**：记录本项目在 Windows 上使用微信开发者工具（含 CLI 与 automator 自动化）的完整流程与实测踩坑，全部内容经 2026-07-29 实机验证。
> **安装路径（本机）**：`D:\soft\微信助手\微信web开发者工具`

---

## 一、准备工作

| 项 | 说明 |
|:--|:--|
| 小程序产物 | `miniapp/dist/`（由 `npm run build:weapp` 生成，weapp 产包） |
| AppID | `touristappid` 游客模式（免登录、免注册，自动化必用） |
| 后端 | NestJS 需先启动：`cd server; npm run start:dev`（端口 3000；Redis 缺席时 TestStore 自动回退内存） |
| 工具安全设置 | IDE 内需开启「设置 → 安全设置 → 服务端口」+ CLI/HTTP 调用，否则 `--auto-port` 起不来 |
| 域名校验 | `project.config.json` 已设 `urlCheck: false`，本地 `http://localhost:3000` 可直连 |

## 二、怎么打开（三种方式）

### 2.1 图形界面手动打开
双击 `微信开发者工具.exe` → 导入项目 → **项目目录选 `miniapp\dist`**（见 §3 大坑1）→ AppID 选"游客模式"。

### 2.2 CLI 打开（⚠ cli.bat 在 PowerShell 下会递归爆栈，见 §5 坑2）
**不要**直接在 PowerShell 里 `& cli.bat ...`。可用方式：

- **cmd 窗口**（非 PowerShell）里直接跑：
  ```bat
  "D:\soft\微信助手\微信web开发者工具\cli.bat" open --project "d:\work\work\code\testsuit\公司\项目\酷酷儿童故事\miniapp\dist"
  ```
- **PowerShell 等效命令**（绕过 cli.bat，实测可用）：
  ```powershell
  $env:ELECTRON_RUN_AS_NODE='1'; $env:cwd=(Get-Location).Path
  $boot="const e=process.argv[1],a=process.argv.slice(2).filter(function(x){return x!=='--electron'});if(!process.env.cwd)process.env.cwd=process.cwd();process.argv=[process.execPath,'--ms-enable-electron-run-as-node',e,'--electron'].concat(a);require(e)"
  & "D:\soft\微信助手\微信web开发者工具\微信开发者工具.exe" -e $boot `
    "D:\soft\微信助手\微信web开发者工具\resources\app.asar.unpacked\js\common\cli\index.js" `
    open --project "d:\work\work\code\testsuit\公司\项目\酷酷儿童故事\miniapp\dist"
  ```
  原理：cli.bat 本质是"用 IDE 的 Electron 以 Node 模式跑内部 CLI 脚本"，上面把这层包装手工展开了。

### 2.3 自动化模式打开（跑 automator 测试用）
把上面命令里的 `open --project …` 换成：
```
auto --project "…\miniapp\dist" --auto-port 9423
```
成功标志：`Test-NetConnection localhost -Port 9423` 为 True。常用其它子命令：`quit`（关工具）、`close --project …`（关项目窗口）。

**★ 一键脚本（推荐）**：`miniapp/scripts/ide-launch.cjs` 已把 §2.2 的 Electron 引导封装好：
```powershell
node miniapp\scripts\ide-launch.cjs auto   # 先 quit 旧实例，再 auto 拉起 + 等 9423 端口就绪（输出 PORT_9423=UP）
node miniapp\scripts\ide-launch.cjs quit   # 只关工具
```
注意：`node cli.js` 直调**不行**（cli.js 内部按 CWD 相对路径找 `js/common/cli/index.js`，会报 MODULE_NOT_FOUND），必须走 Electron 引导（脚本已处理）。

## 三、怎么加载项目（★ 本项目最大的坑）

**必须用 `miniapp\dist` 当项目根目录，不能用 `miniapp\`。**

- `miniapp/dist/` 里自带一份 `project.config.json`（`miniprogramRoot: "./"`），是给 IDE 直开用的；
- `miniapp/` 根下那份 `project.config.json`（`miniprogramRoot: "dist/"`）理论上也合法，但**当前 IDE 版本用它打开会报 `./pages/story/index/index.wxml not found`**——app.json 能读到（标题/导航色正常）但页面文件解析不到，模拟器整页空白；touch 文件触发重编译、reLaunch 都救不回来；
- 症状特征：模拟器只有橙色导航栏 + 一行 `xxx.wxml not found`。遇到即检查项目根目录是不是选错了。

加载后验证三件事：
1. 模拟器渲染出故事首页（学科网格 + 推荐位）；
2. Console 无红色报错（索引 404 说明 server 没起或 `TARO_APP_STATIC_BASE_URL` 不对）；
3. Network 面板索引请求带 `?_v=时间戳`（前端启动级 cache-bust，正常现象）。

## 四、怎么使用（日常开发 / 自动化测试）

### 4.1 日常开发
```powershell
cd miniapp
npm run dev:weapp        # watch 构建，IDE 会随 dist 变化自动重编译
# 真实后端联调构建（一次性）：
$env:TARO_APP_USE_MOCK='false'; npm run build:weapp
```
- `USE_MOCK` 默认 true（脱离后端跑 UI）；接真数据必须显式 `TARO_APP_USE_MOCK=false` 重新构建，是否生效可查 `dist/common.js` 里 `USE_MOCK:!1`（=false）/`USE_MOCK:!0`（=true）。
- 模拟器里音频走 `BackgroundAudioManager`，控制台可 `wx.getBackgroundAudioManager()` 直接查 src/paused/playbackRate。

### 4.2 automator 自动化（miniapp/scripts 现成脚本）
| 脚本 | 用途 |
|:--|:--|
| `weapp-shot.cjs <port> <名字>` | 连上自动化端口，只截当前模拟器画面（最小诊断） |
| `weapp-autotest.cjs connect <port>` | R1-R7 全流程：Tab 互切/换一换/故事灯播暂+倍速/歌曲模式/截图 |
| 其余 `weapp-*.cjs` | 单项诊断（网络/图片/TabBar/导航等） |

截图统一落盘 `工作区/tmp/测试截图/weapp/`。

自建脚本注意两行兼容补丁（新版 IDE 下 automator 库 `checkVersion` 会崩）：
```js
const MPmod = require('miniprogram-automator/out/MiniProgram');
(MPmod.default || MPmod).prototype.checkVersion = async () => {};
```
连接用 `automator.connect({ wsEndpoint: 'ws://localhost:9423' })`（IDE 已由 §2.3 拉起时），不要用 `automator.launch`（它内部又走 cli.bat，会踩坑2）。

## 五、坑清单（全部实测）

| # | 坑 | 现象 | 解法 |
|:--|:--|:--|:--|
| 1 | **项目根选了 `miniapp/` 而非 `miniapp/dist/`** | `pages/xxx.wxml not found`，整页空白 | 永远用 `dist/` 直开（§3） |
| 2 | **PowerShell 里跑 cli.bat** | 刷屏 `Maximum setlocal recursion level reached`，IDE 起不来 | 用 cmd 跑，或用 §2.2 的 PowerShell 等效命令 |
| 3 | **IDE/客户端 HTTP 磁盘缓存索引** | 改了 `_home.json` 等索引，前端仍是几天前的旧数据，重启 IDE 都不清 | 前端已内置启动级 `?_v=时间戳` cache-bust（indexLoader.ts）；手工排查时 Network 面板勾"禁用缓存" |
| 4 | **automator `checkVersion` 崩溃** | `Cannot read properties of undefined (reading 'split')` | 加 §4.2 两行补丁跳过版本检查 |
| 5 | **`--auto-port` 起了但连不上** | connect 一直重试超时 | IDE 安全设置未开服务端口；或上一个 IDE 实例还占着（先 `cli quit` 再拉起） |
| 6 | **构建时环境变量残留**（同一 PowerShell 会话） | 例如设过 `NODE_ENV=production` 后，同会话再启动 server 会触发生产门禁直接拒启 | 构建与起服务用独立终端会话，或用完即重置变量 |
| 7 | **watch 构建期间 IDE 报文件缺失** | taro 先清空 dist 再产出，间隙 IDE 抢编译 | 等构建完成再看模拟器；报错驻留就 touch `dist/app.json` 触发重编译 |
| 8 | **中文路径** | 项目路径含 `公司/项目/酷酷儿童故事` 中文段 | 实测 IDE/CLI/automator 均可用，无需改路径；但脚本内路径务必带引号 |

## 六、常用命令速查

```powershell
# 起后端（先于小程序）
cd server; npm run start:dev

# 构建 weapp（真实后端模式）
cd miniapp; $env:TARO_APP_USE_MOCK='false'; npm run build:weapp

# 拉起 IDE + 自动化端口（PowerShell，见 §2.2 $boot 定义）
& "D:\soft\微信助手\微信web开发者工具\微信开发者工具.exe" -e $boot "D:\soft\微信助手\微信web开发者工具\resources\app.asar.unpacked\js\common\cli\index.js" auto --project "…\miniapp\dist" --auto-port 9423

# 截图验证
cd miniapp; node scripts\weapp-shot.cjs 9423 当前画面

# 全流程自动化
cd miniapp; node scripts\weapp-autotest.cjs connect 9423

# 关闭 IDE
… index.js quit
```
