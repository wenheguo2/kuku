## 一、日常三步（构建 → 重载 → 自动化）

```powershell
cd 项目\酷酷儿童故事\miniapp

# 1 构建（产物进 dist/）
$env:NODE_ENV='production'; $env:TARO_APP_USE_MOCK='false'; npm run build:weapp

# 2 重载 IDE（会重新编译，输出 PORT_9423=UP 即就绪）
node scripts\ide-launch.cjs

# 3 跑自动化脚本（截图落 工作区\tmp\测试截图\weapp\）
node scripts\weapp-shot.cjs 9423 当前画面
```

关工具：`node scripts\ide-launch.cjs quit`

## 二、两条铁律

**1. 项目目录必须选 `miniapp\dist`，不是 `miniapp`**
`dist/project.config.json` 里 `miniprogramRoot` 已处理好。选错会报 `pages/xxx.wxml not found` + 整页空白。
手动导入时同样选 `dist`，AppID 选"游客模式"。

**2. 重载用 `close --project`，不要用 `quit`**
`quit` 不会真正结束 IDE 进程（服务端口仍在监听），之后 `auto` 只是**连回旧实例、旧编译产物**。
症状很坑：**automator 能 `connect` 成功，但 `currentPage`/`screenshot` 全部 `timeout waiting for automator response`**，
console 伴随 `routeDone with a webviewId N is not found`。此时反复重启无用，会白费很多时间。
`scripts\ide-launch.cjs` 已按 `close --project` → `auto --project` 实现，直接用它即可，**不需要手动点【编译】**。

## 三、CLI 原理（脚本内部做的事，一般不用手敲）

PowerShell 里**不能直接跑 `cli.bat`**（会 `Maximum setlocal recursion level reached` 爆栈），
也不能 `node cli.js`（它按 CWD 找内部模块，报 MODULE_NOT_FOUND）。
正确姿势是用 IDE 自带 Electron 以 Node 模式跑内部 CLI：

```powershell
$env:ELECTRON_RUN_AS_NODE='1'; $env:cwd=(Get-Location).Path
$boot="const e=process.argv[1],a=process.argv.slice(2).filter(function(x){return x!=='--electron'});if(!process.env.cwd)process.env.cwd=process.cwd();process.argv=[process.execPath,'--ms-enable-electron-run-as-node',e,'--electron'].concat(a);require(e)"
& "D:\soft\微信助手\微信web开发者工具\微信开发者工具.exe" -e $boot `
  "D:\soft\微信助手\微信web开发者工具\resources\app.asar.unpacked\js\common\cli\index.js" `
  auto --project "…\miniapp\dist" --auto-port 9423
```

子命令：`auto`（开项目+自动化端口）、`close --project X`（关项目窗口）、`quit`（关工具）。
若必须用 cmd 窗口，可直接 `"…\cli.bat" open --project "…\miniapp\dist"`（cmd 下不递归）。

## 四、automator 脚本写法

```js
const automator = require('miniprogram-automator');
// ★必需：跳过版本检查，否则报 Cannot read properties of undefined (reading 'split')
const MPmod = require('miniprogram-automator/out/MiniProgram');
(MPmod.default || MPmod).prototype.checkVersion = async () => {};

const mini = await automator.connect({ wsEndpoint: 'ws://localhost:9423' });
// 启动后页面栈可能为空 → reLaunch 兜底
try { await mini.reLaunch('/pages/story/index/index'); }
catch (e) { await mini.evaluate(() => { wx.reLaunch({ url: '/pages/story/index/index' }); }); }
```

注意：
- 用 `connect` 不用 `automator.launch`（launch 需 cliPath，实测报 "please make sure cliPath is correctly specified"）
- **少用 `reLaunch`**：一个脚本里连续几十次 reLaunch 会把 IDE 路由搞乱导致全超时；优先 `switchTab` / `navigateTo` / 元素 `tap()`
- 原生弹窗（`showModal`/`showActionSheet`）自动化点不到，只能验证入口，实际操作需真机手点
- PowerShell 会吞 `$(...)`，automator 逻辑一律写成 `.cjs` 文件再执行，不要用 `node -e`

## 五、游客模式的固有报错（不是 bug）

Console 常驻这几条红字，无 AppID 环境下正常，**判断业务是否真崩看模拟器有没有渲染出内容**：

`webapi_getwxasyncescinfo:fail` · `Cannot read properties of null (reading 'bg')` · `routeDone ... not found` · `timeout`

## 六、可用脚本一览（`miniapp/scripts/`）

| 脚本 | 用途 |
|:--|:--|
| `ide-launch.cjs` | 重载 IDE + 拉起 9423 端口（日常必用） |
| `weapp-shot.cjs <port> <名>` | 截当前画面（最快探活） |
| `weapp-walk-all.cjs [story\|song\|growth\|parent]` | 四条线全页面走查 |
| `weapp-walk2.cjs a\|b` | 深度交互走查（作品页/搜索/挑战/设置全控件） |
| `weapp-chaos.cjs a\|b` | 破坏性测试（坏参数/连点/边界） |
| `weapp-nitpick.cjs` | 量化度量（触控热区/WCAG 对比度/对齐） |
