## 2. Phase 0: 基础设施 + 生产管道 (第1-3周)

### 2.1 目标
搭建开发环境、部署CDN、完善索引、搭建后端骨架、完成内容生产管道

> **★ 并行原则**: 内容资产(音频/立绘/封面)的持续产出由内容生产线负责,与代码开发**并行推进、互不阻塞**。目录结构和数据schema已确定(见[03-内容架构](03-内容架构与数据流设计.md)),前端/后端可基于现有结构与契约直接开发,无需等待全部内容产出完成。Phase 0 的"生产管道"任务指的是**处理脚本开发**(音频合并/timeline/LRC/透明化),而非内容本身的生成。

## 7. 风险与应对

| 风险 | 等级 | 应对措施 |
|:--|:--|:--|
| 音频文件量太大(62万分段+整曲)，OSS费用高 | 中 | 增量发布，先上热门学科整曲MP3 |
| 小程序包大小限制(2MB主包) | 高 | 分包加载，索引按需获取 |
| 后台播放被微信限制 | 高 | 使用小程序原生音频API，申请后台播放能力 |
| 内容审核风险 | 中 | 提前做内容自查，准备审核材料 |
| 封面图持续制作中(当前674张,非最终数目) | 低 | 持续制作中,首页推荐用已有封面故事 |
| 并发访问CDN | 低 | CDN自动扩容，预热缓存 |
| 小程序审核被拒 | 中 | 提前了解儿童类小程序审核要求 |
| ★ Whisper LRC生成耗时 | 中 | 批量离线处理，非实时，6,338首远端4080 GPU约24小时(✅单首测试通过6.6s) |
| ~~★ 立绘透明化质量不一致~~ | ~~低~~ | ✅已完成1,668张, rembg CPU模式, 边缘halo可接受(不加边缘优化) |
| ★ 横屏三面板兼容性 | 中 | 充分测试不同屏幕尺寸，确保横屏强制旋转正常 |

## 9. 质量保障

### 9.1 测试策略

| 测试类型 | 工具 | 覆盖范围 |
|:--|:--|:--|
| 单元测试 | Jest | 核心服务逻辑 |
| 集成测试 | Jest + Supertest | API接口 |
| E2E测试 | 人工+自动化脚本 | 关键用户路径 |
| 兼容性测试 | 真机+模拟器 | iOS/Android多机型 |
| 性能测试 | Lighthouse + 真机 | 加载速度、内存占用 |
| 内容测试 | 自动化脚本 | 索引完整性、音频可用性、timeline一致性 |
| ★ 横屏测试 | 真机 | 教学播放器横屏三面板在不同机型表现 |
| ★ LRC同步测试 | 自动化脚本 | 歌词时间标签与音频对齐误差 |

### 9.2 发布流程

```
开发环境 (dev)
  ↓ PR Review
测试环境 (staging)
  ↓ 验收测试
预发布环境 (pre-prod)
  ↓ 回归测试
生产环境 (production)
  ↓ 灰度发布
全量发布
```
