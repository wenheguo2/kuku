# 10 - 索引与封面设计方案

> **版本**: v2.0
> **目标读者**: 前端（对接前必读） / 后端

> **目的**: 统一所有故事类型的索引结构，明确封面图层级，规范前端展示逻辑
> **适用范围**: 全部 11 个学科（严格镜像 generated_stories 物理目录，含成长/歌曲 Tab）
> **前端必须先读此文档再对接数据**
> **v2.0 变更**: 索引目录完全镜像物理层级（每个容器目录含 _index.json）；取消“蒙学启蒙”逻辑合并；封面统一 .jpg
> **⚠ 图片格式决策（2026-07-29，用户拍板）**: 全端通用格式——封面/场景图用 **.jpg**、透明立绘用 **.png**，**禁用 webp**（微信开发者工具模拟器不解码 webp，getImageInfo:fail invalid 实测）。存量 31433 张 webp 已全量转换并删除；产图/规格化/索引脚本（05/07/08/09）均已改产 jpg/png。

## 0. App 导航结构

底部 Tab 共 4 项：

| Tab | 名称 | 对应内容 | 数据来源 |
|:--|:--|:--|:--|
| 📖 | **故事** | 默认首页，所有故事学科 | `index/generated_stories/` 下除 学科启蒙、瞎编的歌曲 外的所有学科 |
| 🎵 | **歌曲** | 儿歌专辑 | `index/generated_stories/瞎编的歌曲/` |
| 🌱 | **成长** | 学科启蒙（识字/英语/拼音） | `index/generated_stories/学科启蒙/` |
| 👪 | **家长** | 家长端（独立设计，不在本文档范围） | 另行设计 |

> 学科启蒙、瞎编的歌曲 的索引结构与“故事”Tab 相同（均为镜像目录 + `_index.json`），但前端通过底部 Tab 区分入口，不混在故事列表中。

### 1.2 索引文件类型

| index_type | 层级 | 文件名 | 内容 |
|:--|:--|:--|:--|
| `global_index` | 全局 | `_global.json` | 11个学科列表 + 统计 + 推荐位 |
| `home_index` | 全局 | `_home.json` | 首页推荐：章回大IP池 + 单篇池 + 热点（脚本12 生成，**非物理镜像**） |
| `subject_index` | 学科级 | `{学科}/_index.json` | 学科信息 + categories 子分类列表 |
| `category_index` | 分类级 | `{分类}/_index.json` | 分类下所有条目（entries[] 或 sub_categories[]） |
| `work_index` | 章回作品级 | `{作品}/_index.json` | 完整章回列表 chapters[] |
| `collection_index` | 合集级 | `{合集}/_index.json` | 合集内所有子故事 entries[] |

### 1.3 逻辑合并（已废弃）

> **ℹ️ v2.0 已废弃**：v1.0 中设计的“蒙学启蒙”逻辑合并（蒙学经典+诗词天地→蒙学启蒙）已取消。现在索引严格镜像物理目录，蒙学经典和诗词天地各自为独立学科，前端直接读取其 `_index.json`。

## 2. 核心字段说明（前端必读）

### 2.1 structure_type — 决定内容的组织形式

标记"这个分类是什么类型的内容结构"，前端据此决定渲染方式。

| structure_type | 含义 | 出现在哪 | 前端渲染方式 |
|:--|:--|:--|:--|
| `standalone_collection` | **独立故事集** | `_index.json` 的 categories[] 中 | 展示为「分类卡片」，点进去是故事列表 |
| `chaptered_work` | **章回作品** | `_index.json` 的 categories[] 中 | 展示为「作品卡片」，点进去是章节列表 |
| `mixed` | **混合型** | `_index.json` 的 categories[] 中 | 展示为「混合卡片」，点进去有章回/独立/合集分组 |
| `multi_level` | **多层分类** | `_index.json` 的 categories[] 中 | 展示为「多层卡片」，点进去继续展开子分类（★ 用 `sub_categories[]` 而非 entries[]） |
| `txt_collection` | **文本合集** | categories[]/sub_categories[] 中 | 同独立故事集，entries[] 为 story_card（多见于歌曲学科叶子分类） |
| `standalone` | **独立故事** | entries[] 或 chapters[] 中 | 单条故事，点击直接播放 |
| `chaptered` | **章回条目** | 混合型 entries[] 中 | 作品级卡片，点击展开章节 |
| `collection` | **合集条目** | 混合型 entries[] 中 | 合集卡片，点击展开子故事 |
| `chapter` | **章节** | chaptered_work 的 chapters[] 中 | 章节条目，点击播放该章节 |

### 2.2 display_as — 告诉前端具体渲染卡片类型

| display_as | 含义 | 渲染效果 |
|:--|:--|:--|
| `category_card` | 子分类卡片 | 卡片显示 name + cover + entry_count，点击展开下级 |
| `chaptered_card` | 章回作品卡片 | 卡片显示 work_name + cover + total_chapters，点击展开章节列表 |
| `collection_card` | 合集卡片 | 卡片显示 name + cover + sub_entry_count，点击展开子故事列表 |
| `story_card` | 故事卡片 | 卡片显示 title + level + duration，点击播放 |
| `chapter_item` | 章节条目 | 列表项显示 chapter_index + title + duration，点击播放 |
| `mixed_container` | 混合容器 | 按内部 entries 的类型分组渲染 |

### 2.3 cover — 封面图

```json
"cover": {
  "cover_image_url": "string | null - 封面图片的相对路径（前端基准路径自行配置）",
  "prompt": "string - 生成该封面图的提示词（用于后续重新生成）",
  "style": "string - 插画风格标识",
  "cover_level": "subject|category|work|collection|story|chapter"
}
```

#### cover_level 说明

| cover_level | 用在哪个层级 |
|:--|:--|
| `subject` | 学科级（_index.json 顶层 cover） |
| `category` | 子分类级（_index.json 中每个 category 的 cover） |
| `work` | 章回作品级（混合型 entry.cover） |
| `collection` | 合集级（混合型 entry.cover 或 collection_index 顶层 cover） |
| `story` | 独立故事级（暂不用，从故事 JSON 自身拿） |
| `chapter` | 章节级（暂不用） |

### 3.7 首页推荐 `_home.json`（home_index，脚本12 生成）

> 首页推荐是**数据驱动**的，由 `脚本/12_generate_home_index.py` 扫描真实索引生成，与其他 `_index.json` 平级，放于 `generated_stories/_home.json`。前端走 `indexLoader.loadHome()`（USE_MOCK 时用 mockHomeIndex）。

```json
{

  "index_type": "home_index",
  "generated_at": "2026-07-22T13:59:45",
  "chaptered_works": [
    { "title": "三国演义", "path": "上下五千年/E3历史故事/三国演义", "subject": "上下五千年", "total_chapters": 120, "cover": "covers/generated/.../三国演义.jpg" }
  ],
  "standalone_picks": [
    { "title": "坐井观天", "path": "上下五千年/E1成语故事/坐井观天", "subject": "上下五千年", "level": "L4", "duration_ms": 0, "cover": "" }
  ],
  "hot": [
    { "type": "chaptered", "title": "三国演义", "path": "上下五千年/E3历史故事/三国演义", "subject": "上下五千年", "total_chapters": 120, "cover": "" }
```

| 字段 | 含义 | 前端用途 |
|:--|:--|:--|
| `chaptered_works[]` | 全部章回大IP（扫描全部 work_index） | 首页「📚 大IP章回」，点进 story/work 总入口 |
| `standalone_picks[]` | 仅从「上下五千年」「神州之外」抽的单篇池 | 首页「🎧 单篇推荐」轮动窗口（换一换） |

| `cover` | 相对路径字符串（可空） | 缺图时 emoji 占位 |

## 4. 前端导航与渲染流程

### 4.1 页面层级

```
┌─ 首页 / 学科选择 ──────────────────────────────────┐
│  读取: _global.json                                   │
│  展示: 各学科卡片（cover + subject_name）              │
│  点击 → 进入对应学科                                  │
└──────────────────────────────────────────────────────┘

┌─ 学科页（如：品格养成）─────────────────────────────┐
│  读取: 品格养成/_index.json                           │
│  展示: 学科封面 + categories[] 列表                    │
│  每项: display_as = category_card                      │
│       卡片展示：cover + name + entry_count             │
│  点击 → 进入对应子分类                                │
└──────────────────────────────────────────────────────┘

┌─ 子分类页（如：品格养成/A1勇敢）────────────────────┐
│  读取: 品格养成/A1勇敢.json                           │
│  display_as = category_card                           │
│  展示:                                              │
│    ├─ 推荐区域：从 entries 随机选10条, story_card    │
│    └─ 全部列表：按 entries[] 顺序排列, story_card     │
│  搜索/筛选：全量匹配 entries                          │
│  点击 story_card → 播放故事                           │
└──────────────────────────────────────────────────────┘

┌─ 章回作品页（如：蒙学经典/M1三字经）────────────────┐
│  读取: 蒙学经典/M1三字经.json                         │
│  display_as = chaptered_card                          │
│  展示: work_name + description + chapters[]            │
│  每项: display_as = chapter_item                      │
│       显示：chapter_index + title + duration           │
│  点击 chapter_item → 播放该章节                       │
└──────────────────────────────────────────────────────┘

┌─ 混合型页（如：上下五千年/E3历史故事）──────────────┐
│  读取: 上下五千年/E3历史故事.json                     │
│  display_as = mixed_container                         │
│  展示: 按 structure_type 分组：                       │

│    ├─ 独立故事组（display_as: story_card）             │

```

### 4.2 独立故事集列表展示逻辑

针对 `standalone_collection` 类型：

1. **首次进入页面**：从 entries 中随机选 10 条放在顶部"推荐"区域
2. **向下滚动**：第 11 条起按 entries[] 数组的原始顺序排列
3. **"换一换"**：可提供按钮重新随机推荐
4. **搜索/筛选**：搜索结果是全量匹配，不受随机逻辑影响

### 4.3 封面图使用规则

> **封面路径口径（权威 = 02号 §4.4 / 08号 §0.1）**：索引文件中 `cover_image_url` / `cover_url` 存的是**相对路径**，前端拼接 CDN 基准域名。权威完整路径规则为 `illustrations/covers/generated/{学科}/{分类}/{分类}.jpg`（歌曲封面同理位于 `illustrations/covers/generated/瞎编的歌曲/{分类}/`）。**本文档下方 JSON 示例中出现的扁平写法（如 `/illustrations/covers/A001.jpg`、`/illustrations/song_covers/PL001.jpg`）为简写示意，实际生产以 02号 §4.4 的分层路径为准。**

| 场景 | 读取哪个字段 | fallback |
|:--|:--|:--|
| 首页学科卡片 | `_index.json` 顶层 `cover.cover_image_url` | 用学科名生成占位 |
| 学科页子分类卡片 | `_index.json` 中 `categories[].cover.cover_image_url` | 用分类名生成占位 |
| 混合型章回作品卡片 | `entries[].cover.cover_image_url` | 无 |
| 混合型合集卡片 | `entries[].cover.cover_image_url` | 无 |
| 故事卡片（大部分学科） | 无独立封面，复用所属分类封面 | 使用分类封面 |
| 故事卡片（神州之外） | **每个故事需要独立封面** | 🟡持续制作中(部分已有) |
| 章节条目 | 无独立封面 | 使用作品封面 |

> **Note**:

## 10. 推荐故事配置

### 10.1 配置位置

首页推荐分为三个独立区域，都在 `_global.json` 中配置：

| 区域 | 字段名 | 数量 | 用途 |
|:--|:--|:--:|:--|

**学科和分类推荐**见下方 10.9 节。

### 10.2 配置方式

由运营人员（即你自己）手动编辑 `_global.json` 文件，分别修改三个字段：

- `featured_chaptered_works`: 精选章回列表（4个位置）
- `featured_stories`: 精选故事列表（4个位置）
- `hot_stories`: 热门推荐列表（4个位置）

- 精选章回：建议每月更新一次（大IP相对稳定）

### 10.5 更新流程

**Step 1: 选择推荐故事**

根据以下维度分别选择三个区域的推荐内容：

**精选章回（4个）**:
- **大IP优先**: 西游记、三国、安徒生等知名IP
- **内容完整**: 确保所有章节都已制作完成
- **质量精良**: 配音、音效、插画都达到高标准
- **受众广泛**: 适合大多数年龄段的孩子

**精选故事（4个）**:
- **教育价值**: 能代表学科核心理念，有明确的教育意义
- **制作质量**: 配音、配乐优秀，插画精美
- **经典性**: 孔融让梨、白雪公主等经典故事
- **难度适中**: L3-L5级别，适合大多数孩子

**热门推荐（4个）**:
- **播放数据**: 根据播放量、完播率选择爆款
- **时效性**: 结合节日、季节等主题灵活调整
- **用户反馈**: 关注家长评价、孩子喜好
- **多样性**: 覆盖不同学科、不同分类

**Step 2: 获取故事信息**

从对应的索引文件中获取故事信息：

```bash
# 示例：获取孔融让梨的信息
cat production/index/generated_stories/品格养成/A1勇敢/_index.json | jq '.entries[] | select(.entry_id == "A001_孔融让梨")'
```

**Step 3: 编辑 _global.json**

```bash
# 使用文本编辑器打开
notepad production/index/generated_stories/_global.json

# 或使用 VS Code
code production/index/generated_stories/_global.json
```

分别修改三个字段：
- `featured_chaptered_works`: 替换4个章回作品
- `featured_stories`: 替换4个精选故事
- `hot_stories`: 替换4个热门故事

确保：
- 每个数组数量为4个（不超过4个）
- 每个故事的字段完整（story_id、title、subject等）
- JSON格式正确（无语法错误）

**Step 4: 验证JSON格式**

```bash
# 使用 jq 验证
jq . production/index/generated_stories/_global.json > /dev/null && echo "JSON格式正确" || echo "JSON格式错误"
```

**Step 5: 上传到CDN（生产环境）**

```bash

coscmd upload production/index/generated_stories/_global.json /index/generated_stories/_global.json

# 刷新CDN缓存
coscdn refresh -u https://cdn.kuku-story.com/index/generated_stories/_global.json
```

**Step 6: 前端验证**

1. 打开微信小程序
2. 进入故事首页（S-01）
3. 检查【精选章回】区域是否显示新的4个章回作品
4. 检查【精选故事】区域是否显示新的4个精选故事
5. 检查【热门推荐】区域是否显示新的4个热门故事
6. 点击每个故事，确认可以正常播放

### 10.6 注意事项

⚠️ **重要提醒**:

1. **数量限制**: 
   - `featured_chaptered_works` 最多4个章回作品
   - `featured_stories` 最多4个精选故事
   - `hot_stories` 最多4个热门故事
2. **封面图必须存在**: 确保 `cover_url` 指向的封面图已生成并上传到CDN
3. **故事必须存在**: 确保 `story_id` 对应的故事segments.json文件存在
4. **JSON格式**: 修改后务必验证JSON格式，避免语法错误导致前端解析失败
5. **CDN缓存**: 修改后需要刷新CDN缓存，否则前端可能看到旧数据（缓存24小时）
6. **备份原文件**: 修改前建议备份原文件，以便出错时快速恢复
7. **分层更新策略**: 
   - 精选章回相对稳定，建议每月更新一次
   - 精选故事由人工挑选，建议每两周更新一次
   - 热门推荐根据数据自动计算，建议每周更新一次

1. **横向滚动**: 使用 ScrollView scrollX 组件展示4个歌单卡片
2. **卡片内容**: 显示标题、场景标签、歌曲数量、总时长、封面图
3. **点击跳转**: 点击进入歌单详情页（列出所有歌曲）
4. **UI标识**: 左上角显示“🎼 精选歌单”标签
5. **徽章**: 左上角显示场景标签（如“🌙 睡前”）

**【热门单曲】区域**:
1. **横向滚动**: 使用 ScrollView scrollX 组件展示4个单曲卡片
2. **卡片内容**: 显示标题、时长、播放量、封面图
3. **点击跳转**: 直接播放歌曲或进入歌曲详情页
4. **UI标识**: 左上角显示“🔥 热门单曲”标签
5. **徽章**: 右上角显示“🔥 热门”红色徽章
