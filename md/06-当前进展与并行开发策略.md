### 2.5 ⏱️ TTS 生成完成度与 ETA 测算（R5 上线硬门槛）

> **上线口径（决策 R5）**：MVP 上线的**硬前置门槛 = 故事/教学/歌曲 TTS 全部生成完成**。TTS 是**外部闸门**（受算力/日产能约束），**不可与程序开发并行"抢跑"上线**——代码可以并行就绪，但上线时点由 TTS 完成时间决定。

**当前完成度与剩余量（口径同 08 §0.1，统计日 2026-07-14）**：

| 内容 | 已完成 | 目标 | 剩余 | 完成率 |
|:--|:--|:--|:--|:--|
| 歌曲 MP3 | 4,837 | 6,338 | ~1,501 首 | 76% |
| 教学 F3 拼音 MP3 | 51(课程级刚起步) | ~400 课程 | 大头未生成 | <15% |
| 故事分段(生成中学科) | — | — | 完成率：上下五千年49%/情绪疗愈81%/生活认知61%/自然科学78%/神州之外7% | 见 §2.3 |

**ETA 测算方法（须用实测日产能，不可拍脑袋）**：

```
ETA(天) = 剩余量 ÷ 近7日实测日均产能
```

- **日均产能来源**：歌曲读 MiniMax daemon 日志近7日成品数；故事/教学 TTS 读 TTS worker 日志近7日 MP3 增量。
- **测算示例**（数值待用实测替换）：歌曲若日均 ~200 首，则 1,501÷200 ≈ **8 天**；日均 ~120 首则 ≈ **13 天**。
- **关键路径**：取"歌曲 / 故事剩余学科 / 教学 F3 拼音"三条线 ETA 的**最大值**为 TTS 全完成 ETA，即 MVP 最早可上线时点。

> **落地要求**：每周复盘时刷新本表实测日产能与 ETA，并同步到 [04-开发计划与里程碑](04-开发计划与里程碑.md) 的上线里程碑；ETA 变化超过 ±3 天需在周报标注原因（算力波动/学科难度差异）。

## 3. 并行开发核心原则

### 3.1 一句话原则

> **目录结构和数据格式 = 开发契约。前端/后端现在就能开始,用mock数据或已就绪的部分内容对接;内容持续产出,资产就绪后切换资源URL即可,不改代码。**

### 3.2 三条并行线

```
时间轴 ──────────────────────────────────────────────────────►

[内容生产线]  分段MP3持续产出 ──► 歌曲/封面补齐 ──► (持续)
                   │ (独立推进,产出即入库)
                   │
[生产管道开发] 音频合并─►timeline─►LRC─►透明化─►规格化 ──► (Phase 0)
                   │ (消费已就绪素材,产出线上格式)
                   │
[程序开发线]   后端骨架 ──► 前端Sprint1(故事) ──► Sprint2(歌曲+教学) ──► Sprint3(联调/待上线)
                   │ (基于已确定的契约开发,用已就绪内容做联调)
                   ▼
              代码就绪 ──[等待TTS全完成:R5硬门槛]──► MVP上线
```

### 3.3 前端如何应对"部分内容未就绪"

| 场景 | 应对策略 |
|:--|:--|
| 整曲MP3未生成 | 先用已就绪学科的分段MP3做联调(品格/情绪/生活/自然);播放器逻辑相同,只是seek精度不同 |
| ~~透明底立绘未生成~~ | ~~先用白底立绘对接~~ → ✅已完成1,668张,可直接使用透明底 |
| LRC未生成 | 歌曲播放器先做"无LRC降级为纯文本歌词",LRC就绪后自动启用高亮 |
| _global.json未生成 | 前端先用已产出的10个_index.json做mock,结构一致 |
| 封面持续制作中 | 当前674张已可用,首页推荐用已有封面故事;持续补齐中 |

### 3.4 后端如何应对

后端与内容**完全解耦**——后端只管用户动态数据(登录/收藏/历史/进度/埋点),不碰内容文件。内容走CDN静态JSON。因此**后端可以零等待立即开始**。

## 4. 建议的启动顺序(基于现状优化)

鉴于内容已大量产出、契约已定,建议这样排:

### 第1周:并行启动
- **后端**: NestJS骨架 + PG/Redis + 用户登录API(零内容依赖)
- **前端**: Taro项目初始化 + IndexLoader(用已产出索引对接) + 首页/学科页
- **生产管道**: 音频合并脚本开发(故事full.mp3,优先已就绪学科)
- **内容**: 继续补齐情绪/生活/自然/神州之外音频

### 第2-3周:管道+前端推进
- **生产管道**: timeline.json + LRC + 透明化 + 封面规格化
- **前端**: 故事播放器(用品格养成做联调样本) + 歌曲播放器
- **后端**: 收藏/历史/埋点API

### 第4-6周:MVP功能闭环
- **前端**: 教学横屏三面板(依赖timeline.json就绪) + 通用功能
- **联调**: 全链路打通,内容持续补充

## 5. 资源路径契约(开发对接用)

前端配置一个 CDN base URL,所有资源路径拼接规则(详见02号§4.4):

```
{CDN_BASE}/index/generated_stories/_global.json              # 全局索引
{CDN_BASE}/index/generated_stories/{学科}/_index.json        # 学科索引
{CDN_BASE}/index/generated_stories/{学科}/{分类}/_index.json   # 分类索引（镜像物理目录）
{CDN_BASE}/generated_stories/{学科}/{分类}/{故事名}/segments.json
{CDN_BASE}/audio/{学科}/{分类}/{故事名}/full.mp3              # 故事整曲
{CDN_BASE}/audio/学科启蒙/{F学科}/{课程}/学习{N}/full.mp3     # 教学整曲
{CDN_BASE}/audio/学科启蒙/{F学科}/{课程}/学习{N}/timeline.json
{CDN_BASE}/generated_stories/瞎编的歌曲/{分类}/{子分类}/{歌名}.mp3
{CDN_BASE}/generated_stories/瞎编的歌曲/{分类}/{子分类}/{歌名}.lrc
{CDN_BASE}/illustrations/characters_transparent/{角色}/{pose}/{表情}/{文件}.webp  # 透明底立绘(目标, 1024×1024 RGBA)
{CDN_BASE}/illustrations/covers/generated/{学科}/{分类}/{分类}.webp
{CDN_BASE}/illustrations/scence/{场景}/{文件}.webp  # 场景图(1920×1080横屏16:9)
```

> **开发期本地对接**: 未上CDN前,可把 `production/` 目录作为本地静态资源服务,base URL 指向本地。
