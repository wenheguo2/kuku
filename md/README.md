## 三、编号与权威口径约定（避免跨文档漂移）

为防止同一事实在多份文档里各说各话，约定以下"单一数据源"：

| 主题 | 权威文档 | 说明 |
|:--|:--|:--|
| 资产数量（故事段/歌曲/教学课程/封面等实测值） | **08 §0.1** | 唯一实测数据源；其他文档（含00）一律写"详见08 §0.1"，不复制数字；每次跑完管道脚本刷新一次 |
| 产品决策编号（A-H） | **05-决策点清单** | PRD/02/03 中"决策 F-01"等均指 05 的编号 |
| 架构级关键决策（KD-01~KD-14） | **04 §8.1** | 与 05 的 A-H 独立，末列标注"对应05编号" |
| 建表 SQL / DDL | **08-本地开发实施步骤** | 02 第三章为架构说明，以 08 为建表基线 |
| timeline.json 字段结构 | **07 §脚本2 / 08 §3.2** | 8 字段完整结构；02/03 示例为简化示意 |
| 出题策略 | **02 / 03 / PRD ED-027a** | 已统一为"纯随机不追踪题号" |
| 索引学科数 | **11 个索引学科（含成长/歌曲），其中 9 个故事学科** | 全文统一口径；实测以 08 §0.1 / _global.json 为准（与 md/10 一致） |
| 页面 ID 与页面清单 | **09-页面清单与信息架构** | 跨文档引用页面用 S-/M-/G-/PL-/C-/A-/U-/ADM- 编号 |
| 首页推荐 / `_home.json` | **10 §3.7** | home_index 契约（全章回大IP池 / 单篇池[上下五千年+神州之外] / 热点），由 `脚本/12_generate_home_index.py` 生成；multi_level 用 `sub_categories[]` 见 10 §3.6 |
| API接口定义 | **11-API接口文档** | 前端/后端开发以11号文档为准：统一前缀 `/api/v1`、`{code,message,data}` 包络、服务端判分（题目不下发答案）；索引/媒体走 CDN 静态不经 `/api/v1` |
| 本地缓存/存储 | **Taro.setStorage/getStorage** | 小程序无 `localStorage`，持久化缓存统一用 Taro Storage API（底层 `wx.setStorage`） |
| 搜索选型（MVP） | **PostgreSQL 全文检索** | MVP 复用 PG15 全文检索/`ILIKE`，**不引入 ES/MeiliSearch**（见 02 §1.2 / 11 §8） |
| 样式方案 | **SCSS** | 统一采用 SCSS + CSS 变量/主题 token，不引入 Tailwind（二.19 已统一） |
| 封面/媒体路径 | **02 §4.4** | `illustrations/covers/generated/{学科}/{分类}/`；10号中扁平示例为简写示意 |
| 内容审核方式 | **15 §3 / 05 B-10** | 生成管道内置双重 AI 机审 + 抽审，不逐条人工（决策 R6） |
| 合规资质备案执行 | **17-合规资质备案执行指南** | 15号=“查什么”，17号=“怎么办”，21号=“每步怎么填”；会员+支付进 MVP（决策 R3） |
| 陪伴养成系统（四级朋友/朋友收集册/成就贴纸/话术） | **13-陪伴养成系统设计** | 养成规则与话术替换总表的唯一权威源；展示层话术一律以13号为准（未遇见/已相识/好朋友/好伙伴）；英文技术字段保留 |
| 个性化点名故事（生成/配音/安全口径） | **19-个性化点名故事设计方案** | DeepSeek 直接生成 segments.json → assign_voices → dub_all 多音色配音；含父母声音克隆（MVP）、DeepSeek 双重审查（R6） |
