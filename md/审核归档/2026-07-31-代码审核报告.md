## 3. 发现的问题与修改建议（按优先级）

### P1 高优先级（付费墙 / 数据完整性）

**#1 收藏连播与队列切曲绕过会员门控（防御纵深缺口）**
- 位置：`miniapp/src/services/playbackQueue.ts`（playStory 统一入口）、`miniapp/src/pages/story/player/index.tsx`（openListMenu 收藏连播直接 playStory）
- 事实：会员门控只在播放器页"直接进入"分支检查一次（guardStoryPlay）；**队列内切曲（skip / 自动续播 / 收藏连播）与 resume 续播分支均不再检查**。VIP 到期、切换孩子等身份变化场景下，队列中的池外内容可继续播放；收藏列表若含 VIP 期间收藏的池外内容，到期后仍可连播。
- 建议：在 `playStory` 统一入口内嵌门控（与页面 guard 双保险，形成"一次封装、处处生效"）；或在 `queueAdvance`/`skip` 前对下一项做 `guardStoryPlay` 校验。修复后补齐 md/23 中"非会员收藏连播"的验证记录。

**#2 静态音频直出无防盗链（付费墙可被 URL 直访绕过）**
- 位置：`server/src/main.ts` ServeStatic（production/ → /static）、`miniapp/src/services/membershipGate.ts`
- 事实：membershipGate 自述"入口级软门控，强防需签名 URL 另行评估"；静态服务无签名/防盗链校验，`/static/audio/.../full.mp3` 可被任意客户端直接下载。
- 建议：上线前实施**签名 URL 方案**（服务端按用户签发短时有效 token 化 URL，静态层校验；或 CDN referer/Key 防盗链）。这是当前付费模型下最值得投入的一项。

**#3 输入长度校验缺失（超长入参触发 DB 层 500）**
- 位置：`server/src/modules/progress/progress.controller.ts`（StudyDto.word_text 仅 @IsString）、`test.controller.ts`（getQuiz word_id query 无校验）
- 事实：DB 列 VARCHAR(32/64)，word_text 超长写入会 500；异常过滤器虽不回传原始消息，但用户可见失败且日志噪音大。
- 建议：DTO 补 `@MaxLength(32)` 等，与 DB 定义对齐；query 参数同样校验（可复用 class-validator + whitelist 管道）。

### P2 中优先级（风控 / 文档漂移）

**#4 md/00 §4.3 通过标准与代码漂移**
- 文档写"按学科区分通过标准"，`quiz.util.ts` 注释已自述"真题统一 75%"。**以代码为准**：真实题库（识字 F1/英语 F2）统一 ≥75% 通过。
- 建议：同步 md/00 §4.3（或明确定义分学科标准并实现），消除口径分歧。

**#5 `/orders` GET 列表也限 20/分钟（过严）**
- 位置：`server/src/common/guards/rate-limit.guard.ts`（path.includes('/orders') 一刀切）
- 建议：按 method 拆分——POST 下单限 20/分钟，GET 列表放宽（如 60/分钟），避免正常查询被误伤。

**#6 拉新 inviter 参数无鉴权（可伪造他人 userId 薅免费期）**
- 位置：`miniapp/src/app.tsx`（inviter 捕获）、`server/src/modules/auth/auth.service.ts`
- 事实：inviter 仅服务端做存在性检查 + 10 次上限风控，攻击者可伪造任意 userId 领取 3 天免费期（有上限，低危）。
- 建议：加"inviter ≠ 本人"校验 + 同一邀请码限领（简单方案）；正式运营可改签名邀请链接。

**#7 单实例内存限流（多实例部署失效）**
- 代码注释已自述，属已知取舍。多实例或上云前迁移 Redis 滑动窗口/网关限流即可。

**#8 SONG_SUBJECT 历史命名**
- `miniapp/src/services/songCatalog.ts` 中 SONG_SUBJECT='瞎编的歌曲' 贯穿索引与代码。
- 建议：内容命名治理（如"儿歌金曲"）或加别名映射表，避免上线后出现在任何用户可见文案中。

## 4. 优化方向（架构级）

1. **统一前端门控层**：把 guardStoryPlay 下沉到 playbackQueue.playStory/playSong 内部（一次封装、处处生效），页面层不再各自调用，根除"入口绕过"类问题。
2. **付费资源防盗链落地**：签名 URL（服务端签发 /static 短时签名）或 CDN 防盗链二选一，纳入上线 checklist（md/15）。
3. **限流基础设施化**：内存桶 → Redis 固定/滑动窗口，并配套 admin 登录失败锁定；为多实例部署铺路。
4. **内容命名治理**：建立 subject/别名映射（SONG_SUBJECT 等），索引与展示层解耦，避免历史命名泄漏到用户端。
5. **埋点 → 统计闭环增强**：admin stats 目前仅 4 张卡（活跃/播放/通过/转化），可扩展次日留存、学习漏斗（听→学→挑战→通过）、订单渠道归因。
6. **admin 功能扩展路线**：内容上下架、封面替换、公告配置——写操作上线前需先补"操作人 + 变更记录"审计表。
7. **回归资产沉淀**：miniapp/scripts 中大量 weapp-* 验证脚本（本次按要求跳过审核）建议整理为可重复执行的回归清单，纳入 md/23 验收报告的自动化配套。
8. **支付链路真实验证**：stub fail-closed 设计正确，上线前务必走一遍真实微信支付回调验签 + 权益叠加（base = max(now, 会员期末, free_until)）的端到端用例。
