# 14 - AI 用户体验测试方案

> **定位**: 用 AI 模拟用户对"陪伴养成系统"做上线前体验走查，验证**养成叙事一致性**、**四级朋友进度准确性**、**合规护栏不被突破**。
> **权威源**: 养成规则一律以 [13-陪伴养成系统设计](13-陪伴养成系统设计.md) 为准；门控流程遵循公司《AI用户测试门控规则》。
> **口径**: 全程使用养成话术（未遇见/已相识/好朋友/好伙伴、挑战、朋友收集册、想念中），出现任何教育评测话术（测试/学习阶段/完课率/打分排名）即判定为**体验缺陷**。

---

## 1. 测试目标

| 编号 | 目标 | 通过判据 |
|:--|:--|:--|
| T-1 | 话术一致性 | 全流程 0 处教育评测话术泄漏到展示层 |
| T-2 | 里程碑进度准确 | 听/普通挑战/综合挑战三个里程碑正确点亮四级朋友，无错晋/漏晋 |
| T-3 | 养成正反馈 | 首次听→已相识、挑战→好朋友/好伙伴的晋级即时可见且叙事自洽 |
| T-4 | 朋友收集册 | 收集册按学科正确展示各字/词朋友等级与颜色，好伙伴数量=真实掌握 |
| T-5 | 久别重逢 | 好伙伴超期正确标记"想念中"，再次挑战通过刷新、未通过回落好朋友 |
| T-6 | 合规护栏 | 六条护栏（见 13 号 §1.2）全部不可被突破 |
| T-7 | 睡眠定时 | 定时关闭（睡眠功能）生效；无打卡/连续天数压力设计 |

## 3. 测试场景与脚本

> 每个场景由 AI 用户按"输入动作 → 期望叙事 → 红线检查"三段式走查。

### S-1 首次相遇（首听）
- 动作：新用户第一次完整听完某字词关联故事。
- 期望：该字词从「未遇见」→「已相识」，出现"你和『X』相识了"类叙事。
- 红线检查：不得出现"已学/学会/掌握了 N 个字"等评测话术。

### S-2 普通挑战（交朋友）
- 动作：听过后发起普通挑战并通过。
- 期望：「已相识」→「好朋友」，叙事为"你和『X』成为好朋友"。
- 变体：直接普通挑战（跳过收听）通过 → 直接标记好朋友。
- 红线检查：答错只给答案、不扣分、不出现"测试未通过/不及格"等字样。

### S-3 综合挑战（好伙伴）
- 动作：完成综合挑战。
- 期望：「好朋友」→「好伙伴」，叙事为"你和『X』成了好伙伴"。
- 变体：直接综合挑战通过 → 直接标记好伙伴。
- 红线检查：逐字判定只回落答错字，不做全局打分排名。

### S-4 久别重逢（想念中）
- 动作：让某好伙伴超过 14 天（可配）未再见，再次发起挑战。
- 期望：超期标记"想念中"（仅提醒不降级）；再次挑战通过刷新时间、消除标记；未通过回落好朋友。
- 红线检查：无"连续打卡/断签惩罚"等压力设计。

### S-5 朋友收集册
- 动作：打开朋友收集册，按学科浏览、按"全部/想念中/未遇见"筛选。
- 期望：各字/词朋友等级与四级色正确；好伙伴数量与真实挑战记录一致。
- 红线检查：定位为中性收集统计，不出现"成绩单/排名/分数"。

### S-6 家长视角合规巡检
- 动作：P-3/P-4/P-5 主动寻找红线证据。
- 期望：全产品无充值氪金、无对战、无排名、无学科考试、无打卡压力。
- 红线检查：命中任一即记为 P0 阻塞。

## 4. 合规护栏断言（对应 13 号 §1.2）

| 护栏 | 断言 | 命中处理 |
|:--|:--|:--|
| G1 进度唯一来源=消费内容 | 进度只能通过听故事/挑战推进 | 存在其他推进途径 → P0 |
| G2 全免费不氪金 | 无任何真实货币交易点 | 出现付费点 → P0 |
| G3 无对抗 | 无 PVP/排名/竞争 | 出现对抗 → P0 |
| G4 纯展示型正反馈 | 无打卡/连续天数/积分兑换/经营模拟 | 出现任一 → P0 |
| G5 内容为主养成为辅 | 养成入口不喧宾夺主 | 养成压过内容 → P1 |
| G6 睡眠定时 | 定时关闭（睡眠功能）+无打卡压力 | 缺失 → P1 |

---

## 5. 缺陷分级与门控

| 级别 | 定义 | 门控 |
|:--|:--|:--|
| P0 | 突破合规护栏 / 话术红线泄漏 | **阻塞上线**，必须修复后复测 |
| P1 | 进度判定错误 / 叙事不自洽 / 定时关闭缺失 | 上线前修复 |
| P2 | 文案打磨 / 动效体验 | 可排期迭代 |

**放行标准**：T-1~T-7 全部通过，且 P0=0、P1=0。达标后按公司《AI用户测试门控规则》签收放行。

---

## 6. 执行方式

1. 由 AI 用户 Agent 依 §3 脚本逐场景走查，逐条记录"期望 vs 实际 + 红线判定"。
2. 每轮产出《AI 用户走查报告》（含缺陷清单与分级），归档到会话记录。
3. 修复后回归受影响场景，直至达标。
4. 与 [08-本地开发实施步骤](08-本地开发实施步骤.md) 的联调阶段、[15-上线合规与资质checklist](15-上线合规与资质checklist.md) 联动，合并进上线前门控。

---

## 7. 依赖与短板

- 养成系统前端未实现前，先用设计稿 + Mock 数据做**纸面走查**；实现后转为真机走查。
- 成就贴纸插画由即梦（dreamina）生成，测试期可用占位图，最终以定稿美术复测视觉一致性。
