## 2. 系统架构

### 2.1 五层架构

```
┌─────────────────────────────────────────────────────┐
│ 客户端层 (Client Layer)                              │
│  微信小程序 │ iOS/Android APP │ H5 │ 管理后台        │
├─────────────────────────────────────────────────────┤
│ 接入层 (Gateway Layer)                               │
│  Nginx反向代理 │ 微信登录鉴权 │ CDN边缘节点          │
├─────────────────────────────────────────────────────┤
│ 业务服务层 (Service Layer)                           │
│  索引服务 │ 故事播放 │ 歌曲服务 │ 教学交互            │
│  用户服务 │ 收藏/历史 │ 推荐 │ 搜索 │ 家长控制        │
│  数据统计                                             │
├─────────────────────────────────────────────────────┤
│ 数据存储层 (Data Layer)                              │
│  PostgreSQL(用户数据) │ Redis(缓存) │ OSS(音视频/图片) │
│  JSON索引文件存储                                    │
├─────────────────────────────────────────────────────┤
│ 内容生产层 (Content Pipeline)                        │
│  故事生成 │ TTS音频合成 │ 立绘/封面生成 │ 索引构建    │
└─────────────────────────────────────────────────────┘
```

### 2.2 关键设计决策

#### 决策1: JSON索引文件直接走CDN，不经过后端

**理由**:
- 索引文件是静态JSON，更新频率低
- 全量条目的索引文件总计不大（几十MB，资产数量以 08号 §0.1 实测为唯一源），CDN缓存效率极高
- 减少后端压力，后端只处理用户动态数据

**实现**:
```
索引文件发布流程:
本地构建 → 上传至OSS → CDN刷新 → 客户端直接从CDN拉取JSON

客户端请求索引:
GET https://cdn.example.com/index/generated_stories/品格养成/_index.json
→ CDN边缘缓存命中 → 直接返回JSON
```

#### 决策2: 故事音频合并为整曲MP3，教学音频合并+timeline.json

**理由**:
- 故事纯听，整曲MP3体验更好，无需分段加载
- 教学需立绘/字幕同步，合并MP3 + timeline.json记录每段起始时间戳
- 播放器根据当前进度二分查找timeline.json，定位当前段

**实现**:
```
故事音频:
  ffmpeg合并分段MP3 → 整曲MP3 → CDN
  客户端直接整曲播放

教学音频:
  ffmpeg合并分段MP3 → 整曲MP3 + timeline.json
  timeline.json格式:
  [
    { "seq": 1, "start_ms": 0, "end_ms": 21250, "segment_id": "sp_01467" },
    { "seq": 2, "start_ms": 21250, "end_ms": 26107, "segment_id": "sp_01468" },
    ...
  ]
  客户端: 整曲播放 + 二分查找timeline定位当前段 → 更新立绘/字幕/字词信息
```

> **timeline.json 字段权威口径**：以上为简化示意（仅列定位必需的 seq/start_ms/end_ms/segment_id）。脚本实际产出为 8 字段完整结构 `{seq, start_ms, end_ms, duration_ms, segment_id, character, text, voice_id}`，**以 07 号 §脚本2 / 08 号 §3.2 为准**（详见 §9.1）。

#### 决策3: 后端服务最小化，MVP阶段只做用户相关

**MVP后端API范围**:
- 用户登录（微信授权）
- 收藏增删查
- 播放历史记录
- 数据埋点上报
- 搜索（可选，也可前端本地索引）

**不在MVP范围内的**:
- 推荐算法（先用随机推荐）
- 个性化（先用统一内容）
- 社交功能

## 3. 数据库设计

### 3.1 核心表结构

#### users (用户表)
```sql
CREATE TABLE users (
  id BIGINT PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  openid VARCHAR(64) UNIQUE NOT NULL,
  union_id VARCHAR(64),
  nickname VARCHAR(64),
  avatar_url VARCHAR(512),
  phone VARCHAR(20),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### consent_records（监护人协议同意留痕）
```sql
CREATE TABLE consent_records (
  id BIGINT PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  consent_type VARCHAR(32) NOT NULL DEFAULT 'guardian',
  user_agreement_version VARCHAR(64) NOT NULL,
  privacy_version VARCHAR(64) NOT NULL,
  children_privacy_version VARCHAR(64) NOT NULL,
  agreed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  withdrawn_at TIMESTAMP,
  UNIQUE(user_id, user_agreement_version, privacy_version, children_privacy_version)
);
```

> 登录前由监护人主动勾选，前端提交三份文档版本；服务端校验 `guardian_consent=true` 并留痕。协议正文仍须在提审前由法务定稿。

#### child_profiles (孩子档案表 - 支持多孩子)
```sql
CREATE TABLE child_profiles (
  id BIGINT PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  user_id BIGINT NOT NULL REFERENCES users(id),
  child_name VARCHAR(32) NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_child_user ON child_profiles(user_id);
```

> 字段说明：
> - child_name: 孩子昵称，仅用于档案展示与家长区切换，不要求真实姓名

#### favorites (收藏表)
```sql
CREATE TABLE favorites (
  id BIGINT PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  user_id BIGINT NOT NULL REFERENCES users(id),
  content_type VARCHAR(16) NOT NULL CHECK (content_type IN ('story', 'song', 'lesson')),
  content_id VARCHAR(256) NOT NULL,
  content_title VARCHAR(256),
  subject_id VARCHAR(64),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(user_id, content_type, content_id)
);
CREATE INDEX idx_fav_user_type ON favorites(user_id, content_type);
```

> 设计约束：收藏按家长账号共享，不区分 child_id。

#### play_history (播放历史)
```sql
CREATE TABLE play_history (
  id BIGINT PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  user_id BIGINT NOT NULL REFERENCES users(id),
  child_id BIGINT NOT NULL REFERENCES child_profiles(id) ON DELETE CASCADE,
  content_type VARCHAR(16) NOT NULL CHECK (content_type IN ('story', 'song', 'lesson')),
  content_id VARCHAR(256) NOT NULL,
  content_title VARCHAR(256),
  subject_id VARCHAR(64),
  last_segment INT,
  last_position_ms INT,
  duration_ms INT,
  played_count INT DEFAULT 1,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE UNIQUE INDEX uq_history_child_content ON play_history(child_id, content_type, content_id);
CREATE INDEX idx_history_child_time ON play_history(child_id, updated_at DESC);
```

> 设计约束：播放历史按孩子隔离，前端切换孩子档案后只展示该 child_id 下的历史记录；user_id 用于账号归属校验。

#### learning_progress (学习进度 - 四级阶段系统)
```sql
CREATE TABLE learning_progress (
  id BIGINT PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  user_id BIGINT NOT NULL REFERENCES users(id),
  child_id BIGINT NOT NULL REFERENCES child_profiles(id) ON DELETE CASCADE,
  subject VARCHAR(16) NOT NULL CHECK (subject IN ('识字', '英语', '拼音')),
  word_id VARCHAR(64) NOT NULL,
  word_text VARCHAR(32),
  current_stage SMALLINT NOT NULL DEFAULT 0 CHECK (current_stage IN (0, 1, 2, 3)),
  study1_completed BOOLEAN DEFAULT FALSE,
  study2_completed BOOLEAN DEFAULT FALSE,
  study3_completed BOOLEAN DEFAULT FALSE,
  test_passed BOOLEAN DEFAULT FALSE,
  comprehensive_passed BOOLEAN DEFAULT FALSE,
  last_study_type VARCHAR(16) CHECK (last_study_type IN ('study1', 'study2', 'study3', 'test', 'comprehensive')),
  test_count INT DEFAULT 0,
  comprehensive_count INT DEFAULT 0,
  used_question_ids JSONB DEFAULT '[]',
  last_test_failed BOOLEAN DEFAULT FALSE,
  last_test_at TIMESTAMP,
  retry_used INT DEFAULT 0,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(child_id, word_id)
);
CREATE INDEX idx_progress_child ON learning_progress(child_id);
CREATE INDEX idx_progress_subject ON learning_progress(child_id, subject);
CREATE INDEX idx_progress_stage ON learning_progress(child_id, subject, current_stage);
-- 只升不降·无惩罚·无间隔复习：已移除 last_reviewed_at/review_due_at/needs_review 三列与 idx_progress_review。
```

> 字段说明：
> - current_stage: 当前朋友等级(0=未遇见, 1=已相识, 2=好朋友, 3=好伙伴)，层级覆盖关系；等级由里程碑达成情况驱动(听/普通挑战/综合挑战)。注：stage/test 等为历史技术字段名，展示层统一用养成话术，见 13-陪伴养成系统设计
> - study1/2/3_completed: 学习1/2/3是否完成（所有学习模块统一，付费边界在课程级别而非学习模块级别）
> - test_passed: 普通挑战是否通过（好朋友）
> - comprehensive_passed: 综合挑战是否通过（好伙伴）
> - test_count/comprehensive_count: 普通挑战/综合挑战次数
> - used_question_ids: 已出过的题号JSON数组(纯随机出题，此字段已废弃)
> - last_test_failed: 上次挑战是否未通过（用于"上次未通过"提示）
> - last_test_at: 最后挑战时间
> - retry_used: 历史遗留字段；无惩罚后普通挑战可无限重试，不再使用该计数
> - ★ 只升不降·无惩罚·无间隔复习：已移除 last_reviewed_at/review_due_at/needs_review 三列

#### comprehensive_tests (综合挑战记录)
```sql
CREATE TABLE comprehensive_tests (
  id BIGINT PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  user_id BIGINT NOT NULL REFERENCES users(id),
  child_id BIGINT NOT NULL REFERENCES child_profiles(id) ON DELETE CASCADE,
  subject VARCHAR(16) NOT NULL CHECK (subject IN ('识字', '英语', '拼音')),
  trigger_type VARCHAR(8) NOT NULL CHECK (trigger_type IN ('auto', 'manual')),
  word_ids JSONB NOT NULL,
  question_ids JSONB NOT NULL,
  answers JSONB,
  per_char_results JSONB,
  correct_count INT,
  passed BOOLEAN,
  tested_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_comp_test_child ON comprehensive_tests(child_id, tested_at DESC);
```

> 字段说明：
> - trigger_type: 触发方式(auto=攒满10个自动触发, manual=用户主动选字触发)
> - word_ids: 参与综合挑战的10个word_id列表
> - question_ids: 实际出的题目ID（每字按学科结构出题：1X+2X+3-9X）
> - answers: 用户答题记录JSON
> - per_char_results: 逐字判定结果JSON，格式如 `[{"word_id":"xxx","passed":true,"1x_correct":true,"2x_correct":false,"3x_correct":[true,true]},...]`
> - correct_count: 通过的字/词数（非题目数）
> - passed: 是否通过(8/10字通过=通过)
> - ★ 只升不降：综合挑战未通过时，答错的字/词（per_char_results 中 passed=false）**保持原等级，不回落**；答对才晋升至好伙伴

#### parent_settings (家长设置 - 无密码/无时长限制)
```sql
CREATE TABLE parent_settings (
  id BIGINT PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  user_id BIGINT UNIQUE NOT NULL REFERENCES users(id),
  timer_minutes INT DEFAULT 30,
  settings_json JSONB,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

> 字段说明：timer_minutes=定时关闭分钟数（15/30/45/60/90/自定义），settings_json=其他家长设置(JSONB)

#### memberships (会员表)
```sql
CREATE TABLE memberships (
  id BIGINT PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  user_id BIGINT NOT NULL REFERENCES users(id),
  plan_type VARCHAR(16) NOT NULL CHECK (plan_type IN ('monthly', 'quarterly', 'yearly')),
  status VARCHAR(16) NOT NULL CHECK (status IN ('active', 'expired', 'cancelled')),
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,
  auto_renew BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_membership_user ON memberships(user_id, status);
```

> 字段说明：plan_type=套餐(monthly月/quarterly季/yearly年)，status=状态(active有效/expired过期/cancelled取消)，start_date/end_date=会员有效期，auto_renew=自动续费（与08实施步骤DDL保持一致）

#### orders (订单表)
```sql
CREATE TABLE orders (
  id BIGINT PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  user_id BIGINT NOT NULL REFERENCES users(id),
  order_no VARCHAR(64) UNIQUE NOT NULL,
  plan_type VARCHAR(16) NOT NULL CHECK (plan_type IN ('monthly', 'quarterly', 'yearly')),
  amount DECIMAL(10,2) NOT NULL,
  payment_channel VARCHAR(16),
  status VARCHAR(16) NOT NULL CHECK (status IN ('pending', 'paid', 'failed', 'refunded', 'cancelled')),
  paid_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_orders_user ON orders(user_id, created_at DESC);
CREATE INDEX idx_orders_status ON orders(user_id, status);
```

> 字段说明：order_no=订单号(唯一)，plan_type=购买的套餐，amount=金额(元)，payment_channel=支付渠道(微信/支付宝/...)，status=支付状态(待支付/已支付/失败/已退款/已取消)，paid_at=支付时间（与08实施步骤DDL保持一致）

#### events (事件埋点表)
```sql
CREATE TABLE events (
  id BIGINT PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  user_id BIGINT REFERENCES users(id),
  child_id BIGINT REFERENCES child_profiles(id),
  event_name VARCHAR(64) NOT NULL,
  event_type VARCHAR(32) NOT NULL CHECK (event_type IN ('story', 'song', 'lesson', 'parent', 'system')),
  content_type VARCHAR(16) CHECK (content_type IN ('story', 'song', 'lesson')),
  content_id VARCHAR(256),
  properties JSONB,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_event_user ON events(user_id, created_at DESC);
CREATE INDEX idx_event_name ON events(event_name, created_at DESC);
```

> 字段说明：event_name=事件名(story_play/story_complete/lesson_study/test_pass等)，event_type=事件大类，content_type/content_id=关联内容，properties=扩展属性(JSONB，如播放时长、答题结果等)

#### child_achievements (孩子成就表 - 陪伴养成正反馈)
```sql
CREATE TABLE child_achievements (
  id BIGINT PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  child_id BIGINT NOT NULL REFERENCES child_profiles(id) ON DELETE CASCADE,
  achievement_type VARCHAR(32) NOT NULL CHECK (achievement_type IN ('sticker', 'title', 'tree_node')),
  achievement_key VARCHAR(64) NOT NULL,
  achievement_name VARCHAR(64) NOT NULL,
  subject VARCHAR(16) CHECK (subject IN ('识字', '英语', '拼音')),
  metadata JSONB,
  earned_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(child_id, achievement_type, achievement_key)
);
CREATE INDEX idx_achievement_child ON child_achievements(child_id, achievement_type);
```

> 字段说明：
> - achievement_type: 成就类型(sticker=贴纸, title=称号, tree_node=成长树/朋友册节点)
> - achievement_key: 成就唯一标识(如"sticker_10", "sticker_50", "title_literacy_master")
> - achievement_name: 成就名称(如"识字小能手", "识字小达人")
> - subject: 关联学科(识字/英语/拼音)，可为NULL(通用成就)
> - metadata: 扩展信息(JSONB，如图标URL、描述等)
> - earned_at: 获得时间

## 4. API设计

### 4.1 API规范

- RESTful风格
- 统一前缀 `/api/v1`
- JWT Bearer Token认证
- 响应格式统一

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 4.2 核心API列表

#### 用户相关
| 方法 | 路径 | 说明 |
|:--|:--|:--|
| POST | /api/v1/auth/login | 微信登录 |
| POST | /api/v1/auth/logout | 退出登录（使当前 token 失效） |
| GET | /api/v1/user/profile | 获取用户信息 |
| PUT | /api/v1/user/profile | 更新用户信息 |
| DELETE | /api/v1/user | 账号注销与数据删除（合规，二次确认后删除用户及名下全部数据，见 11号 §2.5） |

#### 收藏
| 方法 | 路径 | 说明 |
|:--|:--|:--|
| GET | /api/v1/favorites | 获取收藏列表 |
| POST | /api/v1/favorites | 添加收藏 |
| DELETE | /api/v1/favorites/{id} | 取消收藏 |

#### 播放历史
| 方法 | 路径 | 说明 |
|:--|:--|:--|
| GET | /api/v1/history?child_id={id} | 获取指定孩子的播放历史 |
| POST | /api/v1/history | 记录播放历史（body含child_id） |
| DELETE | /api/v1/history/{id} | 删除单条历史 |
| DELETE | /api/v1/history?child_id={id} | 清空指定孩子的历史 |

#### 成长进度与挑战
| 方法 | 路径 | 说明 |
|:--|:--|:--|
| GET | /api/v1/progress/{subject}?child_id={id} | 获取指定孩子的学科朋友等级列表（返回该学科所有字/词的current_stage及状态） |
| GET | /api/v1/progress/{subject}?child_id={id}&stage={n} | 按等级筛选（stage=0未遇见/1已相识/2好朋友/3好伙伴） |
| POST | /api/v1/progress/study | 提交学习完成（body含child_id、word_id、study_type） |

## 7. 安全设计

### 7.1 内容安全

- 音频/图片通过CDN签名URL访问，防止盗链
- JSON索引文件公开访问（无敏感信息）
- 用户API需JWT认证
- ~~家长功能需二次密码验证~~ → 已删除家长锁（决策F-01）

### 7.2 儿童信息保护

- 采用最小化采集原则：仅存孩子昵称、学习进度、播放历史、成就等产品运行所需信息
- 孩子档案仅使用昵称，不要求真实姓名
- 不采集孩子生日、学校、住址、证件等非必要敏感信息
- 不做精准画像广告
- 遵守《儿童个人信息网络保护规定》
- 隐私政策明确告知

### 7.3 API安全

- HTTPS强制
- 请求频率限制 (Rate Limiting)
- JWT Token有效期2小时，Refresh Token 30天
- 关键操作（删除等）需二次确认
