## 通用参数

所有脚本支持以下命令行参数：

| 参数 | 说明 |
|:--|:--|
| `--test N` | 测试模式：只处理前 N 个项目 |
| `--dry-run` | 扫描模式：只统计不执行 |
| `--force` | 强制重新生成（跳过已存在检查） |

**合并脚本（01/02）额外参数**：

| 参数 | 默认值 | 说明 |
|:--|:--|:--|
| `--gap SEC` | 故事0.3 / 教学0.5 | 段间静音时长（秒），0=不加间隔 |
| `--no-normalize` | (关闭) | 不做音量归一化（默认逐段 loudnorm） |
| `--no-fade` | (关闭) | 不添加淡入(0.1s)/淡出(0.3s) |
| `--wpm-low N` | 90 | WPM下限：低于此值提速到此值 |
| `--wpm-high N` | 300 | WPM上限：高于此值降速到此值 |
| `--allow-incomplete` | （已默认开启） | 脚本1/2 均默认允许缺段合并，此参数保留兼容 |
| `--workers N` | 2 | 并行线程数 |

> **音量归一化说明**：实测分段MP3音量差异最大5.1dB（同一故事内 -21.2 ~ -16.1 dB）。
> - v6 默认采用**逐段 loudnorm**（EBU R128, I=-16 LUFS, TP=-1.5, LRA=11），比整曲归一化更精确，短段无伪影
> - `--no-normalize`：不归一化，仅 atempo + concat + fade

> **★ 语速说明（现行策略：宽区间 WPM 归一化 90-300）**：
> - ★ 脚本1/2 均采用 **WPM 区间归一化**：90-300 区间不改，>300 降速到 300，<90 加速到 90（只修正极端值，绝大多数段原速）
> - 区间常量定义在 `common.py` 的 `WPM_LOW=90 / WPM_HIGH=300`，可用 `--wpm-low/--wpm-high` 临时调整
> - 历史背景：v6 曾用 180-210 窄区间（变速面大，影响吟诵/韵律及角色自然度），后一度改全部原速，现改为 90-300 宽区间只剪极端

> **完整性校验说明**：segments.json 中每个段落都必须有对应的音频文件。
> - 默认行为（脚本1/2）：**缺段仍合并**，缺失段跳过，缺段明细（seq/id/character/text）记录到 `脚本/logs/{01_story|02_teaching}_merge_incomplete.json`，供后续补配音
> - ★ 脚本1/2 均为**覆盖生成模式**：不检查已有 full.mp3（及 timeline.json），每次运行重新生成并覆盖（无排除学科，蒙学经典/诗词天地也参与）

## 各脚本详细说明

### 脚本1：故事整曲MP3合并 `01_merge_story_mp3.py` (v6)

**功能**：遍历 `production/audio/` 下所有故事目录，将分段 MP3 合并为一个 `full.mp3`

**v6 关键改进**：
- ★★ **WPM区间归一化(90-300)**：区间内不改，>300降速、<90加速，只修正极端值
- ★ **覆盖生成**：已有 full.mp3 每次重新生成覆盖（无断点跳过，无排除学科）
- ★ **逐段 loudnorm 归一化**：每段独立 EBU R128 归一化（比整曲更精确，短段无伪影）
- ★ 输出 96kbps CBR 24kHz mono（v4是64k，音质更好）
- ★ segments.json 找不到 → 跳过并报错（不 fallback 到文件名排序）
- ★ 未匹配MP3 → 告警并跳过（不追加到末尾）
- ★ ffprobe 超时 → 跳过并报错（不返回0.0）
- 2线程并行（v4是4线程，逐段处理更吃CPU）
- 启动时自动清理 `_tmp_merge` 临时目录

**处理流程**：
1. 读取 `segments.json`，按 `seq` 字段排序
2. 用 `segment.id` 匹配音频文件（`{id}.mp3`）
3. 校验完整性：缺段仍合并（默认），缺段明细记入 incomplete 日志
4. 逐段处理：
   a. ffprobe 实测原始时长，算 WPM；90-300 区间内 atempo=1.0，超出才算 atempo
   b. ffmpeg 编码：`atempo(如需) + loudnorm` 滤镜
5. 合并所有 normalize 后的段 + 静音间隔 → `full.mp3`（含淡入淡出）

**输入**：`production/audio/{学科}/{分类}/{故事名}/sp_00001.mp3, sp_00002.mp3, ...`
**输出**：`production/audio/{学科}/{分类}/{故事名}/full.mp3`

**命名格式兼容**：
- `sp_*.mp3` — 双界之门/品格养成/上下五千年/情绪疗愈/生活认知/自然科学/神州之外
- `seg_*.mp3` — 蒙学经典
- `intro_poem_seq_*.mp3` / `intro_*.mp3` / `outro_*.mp3` — 诗词天地

**参数**：

| 参数 | 默认值 | 说明 |
|:--|:--|:--|
| `--gap SEC` | 0.3 | 段间静音时长（秒） |
| `--no-normalize` | (关闭) | 不做音量归一化 |
| `--no-fade` | (关闭) | 不添加淡入淡出 |
| `--wpm-low N` | 90 | WPM下限 |
| `--wpm-high N` | 300 | WPM上限 |
| `--allow-incomplete` | （已默认开启） | 缺段仍合并，缺段明细记日志 |
| `--workers N` | 2 | 并行线程数 |
| `--test N` | 0 | 测试模式：只处理前 N 个 |
| `--dry-run` | (关闭) | 只扫描统计 |
| `--force` | (关闭) | 强制重新生成 |

**使用方式**：
```bash
cd "D:/work/work/code/testsuit/公司/项目/酷酷儿童故事"

# 全量执行（WPM 90-300 宽区间归一化 + 覆盖生成，全部学科含蒙学经典/诗词天地）
python 脚本/01_merge_story_mp3.py

# 测试模式
python 脚本/01_merge_story_mp3.py --test 5

# 自定义间隔
python 脚本/01_merge_story_mp3.py --gap 0.5

# 缺段默认也会合并，缺段明细（故事/id/text）自动记到 logs/01_story_merge_incomplete.json
python 脚本/01_merge_story_mp3.py

# 4线程并行（CPU富裕时）
python 脚本/01_merge_story_mp3.py --workers 4
```

**日志输出**：`脚本/logs/01_story_merge.log` + `01_story_merge_failed.json` + `01_story_merge_incomplete.json`（缺段明细：故事/seq/id/character/text）

### 脚本2：教学合并MP3 + timeline.json `02_merge_teaching_mp3.py` (v6)

**功能**：遍历 `production/audio/学科启蒙/` 下所有课程，对每个 学习1/学习2/学习3/习题/编号N 子目录：
1. ★ 读取 `segments.json`，按 `seq` 排序，用 `id` 匹配音频文件
2. ★ 完整性校验：缺段仍合并（默认），缺段明细记入 incomplete 日志
3. ★★ WPM区间归一化(90-300)：区间内不改，超出才修正，逐段 loudnorm 照常
4. 合并分段 MP3 → `full.mp3`（含静音间隔 + 淡入淡出）
5. ★ 生成 `timeline.json`（时长 = normalize 后 ffprobe 实测，精准对齐，0.00s 误差）
6. ★ 覆盖生成：已有 full.mp3/timeline.json 每次重新生成覆盖（无断点跳过）

**v6 关键改进**：
- ★★ **WPM区间归一化(90-300)**：区间内不改，超出才修正，只剪极端值
- ★ **timeline 简化精准**：直接用 normalize 后的 ffprobe 实测时长
  - atempo 在逐段 normalize 中完成，ffprobe 测的是最终时长
  - gap 不受 atempo 影响（静音在 concat 中添加）
  - 实测 timeline 误差：**0.00s**
- 输出 96kbps CBR 24kHz mono
- segments.json 找不到 → 跳过并报错
- ffprobe 超时 → 跳过并报错
- 2线程并行
- 启动时清理 `_tmp_merge`

**输入**：`production/audio/学科启蒙/{F1识字|F2英语|F3拼音}/{课程名}/{学习1|学习2|学习3|习题}/...mp3`
**输出**：
- `production/audio/学科启蒙/.../学习1/full.mp3`
- `production/audio/学科启蒙/.../学习1/timeline.json`

**timeline.json 格式**（v6 — ffprobe实测，精准对齐）：
```json
[
  {"seq": 1, "start_ms": 0,     "end_ms": 12500,  "duration_ms": 12500,
   "segment_id": "的_s02_q001", "character": "旁白", "text": "阳光明媚的花园里...", "voice_id": "V-ADW-01"},
  {"seq": 2, "start_ms": 13000, "end_ms": 17000,  "duration_ms": 4000,
   "segment_id": "的_s02_q002", "character": "酷酷", "text": "桃子，你看小熊猫在做什么？", "voice_id": "V-TN-01"},
  {"seq": 3, "start_ms": 17500, "end_ms": 25000,  "duration_ms": 7500,
   "segment_id": "的_s02_q003", "character": "桃子", "text": "他拿着竹竿在戳一朵花呢。", "voice_id": "V-TN-04"}
]
```
> ★ `duration_ms` = normalize 后 ffprobe 实测时长（就是最终播放时长）
> ★ `start_ms` = 上一段 `end_ms` + gap（gap 不受 atempo 影响）
> ★ 实测验证：timeline 最后一段 `end_ms` 与 `full.mp3` ffprobe 实测时长误差 = **0.00s**

**参数**：同脚本1，默认 gap=0.5

**使用方式**：
```bash
# 全量执行（默认 gap=0.5, 逐段loudnorm, fade, WPM区间90-300, 覆盖生成, 2线程）
python 脚本/02_merge_teaching_mp3.py

# 测试模式
python 脚本/02_merge_teaching_mp3.py --test 5

# dry-run 查看WPM分布
python 脚本/02_merge_teaching_mp3.py --dry-run --test 10

# 自定义WPM区间
python 脚本/02_merge_teaching_mp3.py --wpm-low 170 --wpm-high 200
```

**日志输出**：`脚本/logs/02_teaching_merge.log` + `02_teaching_merge_failed.json` + `02_teaching_merge_incomplete.json`（缺段明细：单元/seq/id/character/text）

### 脚本3：歌曲LRC生成 `03_generate_lrc.py`

**功能**：用 Whisper medium 模型对歌曲 MP3 转录，结合 TXT 歌词生成 LRC 时间标签文件

**⚠️ 此脚本在远端 4080 SUPER 机器上运行！**

**输入**（远端路径）：`D:\lrc_work\songs\{分类}\{子分类}\{歌名}.mp3` + `{歌名}.txt`
**输出**（远端路径）：`D:\lrc_work\output\{分类}\{子分类}\{歌名}.lrc`

**LRC 格式**：
```
[ti:一个人的旅行]
[00:01.50]第一行歌词
[00:05.20]第二行歌词
```

**使用方式**（远端执行）：
```bash
# 1. 本机先传输歌曲到远端
python 脚本/transfer_songs_to_remote.py

# 2. SSH到远端（主机/账号/密码见本地 .env，不入库）
ssh $REMOTE_USER@$REMOTE_HOST

# 3. 远端执行
cd D:\lrc_work
python 03_generate_lrc.py                    # 全量执行
python 03_generate_lrc.py --test 5           # 只处理前5首
python 03_generate_lrc.py --dry-run          # 只扫描
python 03_generate_lrc.py --model large-v3   # 用large-v3模型（精度最高）

# 后台运行（长时间任务推荐）
start /b python 03_generate_lrc.py > lrc_run.log 2>&1

# 4. 完成后本机传回LRC
python 脚本/fetch_lrc_from_remote.py
```

**模型选择**：
| 模型 | 大小 | 精度 | 速度(4080) | 推荐场景 |
|:--|:--|:--|:--|:--|
| tiny | 39MB | 低 | ~1s/首 | 快速验证 |
| base | 74MB | 中 | ~1.5s/首 | — |
| small | 244MB | 中高 | ~2s/首 | — |
| **medium** | **1.5GB** | **高** | **~3-5s/首** | **默认推荐** |
| large-v3 | 3GB | 最高 | ~8-10s/首 | 精度优先 |

**预估**：6,338首 × medium模型 × 4080 GPU ≈ 5-8秒/首 ≈ **~24小时**

### 脚本10：歌曲批量生成（正序）`batch_songs.py`

**功能**：扫描 `production/generated_stories/瞎编的歌曲/` 下所有歌词 `.txt`，通过 MiniMax 音乐 WebSocket 接口批量生成歌曲音频（MP3），下载到对应歌曲目录，进度写入 `_generation_progress.json` 实现断点续传。

**分类**：这是**内容生成**类脚本（与前面 01–09 的「生产管道」不同——01–09 把已生成的故事/TTS 转为线上格式，本脚本生成歌曲本体）。配套倒序版本为 `batch_songs_reverse.py`（反向遍历，逻辑相同，运行于 `minimax_music/` 目录，未复制到此目录）。

**核心机制**：
- ★ **版本生成**：每首歌按所在文件夹生成不同版本（常规：摇篮曲 + 派对舞曲；青春之歌：每首自带风格自定义版；大孩儿进阶：空灵版；纯音乐文件夹：纯音乐版）。具体版本由 `get_versions_for_folder()` 按路径动态决定。
- ★ **MODEL_VERSION 开关**（脚本顶部常量，需改文件后重启进程生效）：
  - `music-2.6`：仅生成带歌词歌曲，**纯音乐/BGM 文件夹自动跳过**，每天 500 首额度
  - `music-3.0`：全功能（带歌词 + 纯音乐），每天 500 首额度
  - 建议正序 2.6 + 倒序 3.0 双跑 → 每日合计 1000 首额度
- ★ **断点续传**：重启时只认 `status == "success"`；`failed` / `audit_skip` / 未跑过的版本会重新入队重试。入队前还会校验磁盘是否已存在 >10KB 音频文件，有则补标 success 跳过，不浪费额度。
- ★ **PID 锁 + 进度锁**：本脚本同目录生成 `_batch.lock`（写入 `os.getpid()`）防重复启动；进度文件 `_generation_progress.json` 写操作带 `.lockdir` 锁，正/倒序锁目录各自独立。

**输入**：`production/generated_stories/瞎编的歌曲/{分类}/{子分类}/{歌名}.txt`
**输出**：`.../{歌名}.mp3`（及版本后缀文件，如 `（纯音乐版）.mp3`、`_Hi.mp3`）
**进度文件**：`production/generated_stories/瞎编的歌曲/_generation_progress.json`（正/倒序共用同一进度文件）

**启动方式**：
```bash
# 直接前台运行（仅调试/短跑用，Ctrl+C 即停）
python 脚本/batch_songs.py

# 推荐：用 run_detached.py 脱离终端后台常驻（位于 minimax_music/，同时拉起正序+倒序）
cd minimax_music
python run_detached.py
```

**命令行参数**：

| 参数 | 说明 |
|:--|:--|
| （无参） | 继续生成（自动跳过已完成） |
| `--reset` | 清除 `_generation_progress.json` 全部进度，从头开始 |
| `--dry-run` | 仅扫描并打印任务列表，不实际请求生成 |
| `--status` | 打印当前进度统计（已完成/失败/剩余）后退出 |
| `--max N` | 最多生成 N 条（测试用） |

**使用方式**：
```bash

python 脚本/batch_songs.py --status

# 预览待生成任务（不执行）
python 脚本/batch_songs.py --dry-run

# 切换模型版本：编辑脚本顶部 MODEL_VERSION = "music-2.6" 或 "music-3.0"，保存后重启进程
# 停止：结束 batch_songs.py 进程，并删除其同目录 _batch.lock 即可
```

**依赖**：`websockets`、`aiohttp`（MiniMax 音乐 WebSocket 接口，需联网）

> ⚠️ **注意**：脚本内 `ROOT_DIR` 为硬编码绝对路径，复制到本目录后无需修改即可运行；但 `MODEL_VERSION` 切换必须改文件并重启进程才生效。正/倒序共用同一进度文件、各自独立锁目录，可并行运行。

### 脚本11：历史故事封面批量生成 `10_generate_history_story_covers.py`

**功能**：扫描 `production/generated_stories/上下五千年/E3历史故事/其他/` 下全部历史故事（当前 146 个，每个仅含 `*.json` 故事数据、无封面图），为每个故事生成封面图。每个故事 **3 款提示词 × 3 张 = 9 张**：

- **A 全景**：宽幅全景构图，展现历史场景与整体氛围
- **B 角色特写**：聚焦故事主角的温馨特写镜头（⚠️ 不强制酷酷/桃子出现在画面中）
- **C 高潮瞬间**：捕捉故事最动人的高潮瞬间，富有戏剧张力

**提示词自动生成**：读取每个故事的 `synopsis` + `illustration_style`（中文，即梦原生支持），自动拼接成封面提示词，无需手写。按需求**去掉了点名酷酷/桃子**的措辞，仅以角色参考图（酷酷/桃子）维持整体绘本画风一致，画面更自然。

**即梦并发调度（严格对齐《即梦Dreamina》手册 §7，防封号）**：
- ★ **7 路并发**（`--workers` 默认 7，硬编码上限 7，不可超过）
- ★ **首轮 2s 错峰**：启动 Worker 时每隔 2s 启一个，避免初始请求风暴
- ★ **gen 后 sleep 2s** 再 download，自然错峰（download 不占即梦 GPU 槽位）
- ★ **超时拆分**：`submit`（图生图上传）超时 300s（纯 I/O 不占 GPU）；`query_result` 轮询总窗口 60s
- ★ **全局熔断**：5 分钟窗口内失败总数 ≥10 → 全体暂停 5 分钟冷却后继续

**断点续做**：已存在且合法的 PNG 自动跳过（被杀进程留下的残缺文件会被重生成）；`--force` 强制重生成；`--dry-run` 仅统计；`--test N` 只处理前 N 个故事。**并发与故事/提示词种类无关**——每个(故事×A/B/C×第几张)都是独立任务，统一进 7 路队列。
