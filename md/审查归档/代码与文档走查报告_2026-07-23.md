### 3.2 代码具体问题

#### 问题 S-1：`rate-limit.guard.ts` 限流为单实例内存模式
- **严重程度**: 中
- **位置**: [rate-limit.guard.ts](file:///d:/work/work/code/testsuit/公司/项目/酷酷儿童故事/server/src/common/guards/rate-limit.guard.ts)
- **描述**: 限流使用 `Map<string, Bucket>` 内存存储，多实例部署时各自独立计数，无法有效限流。代码注释已承认"扩为多实例时应把计数迁移到 Redis 或网关"。
- **建议**: 尽早迁移到 Redis 实现（项目已依赖 ioredis），使用滑动窗口或令牌桶算法。

#### 问题 S-2：`quiz.util.ts` 题库为硬编码占位
- **严重程度**: 中
- **位置**: [quiz.util.ts](file:///d:/work/work/code/testsuit/公司/项目/酷酷儿童故事/server/src/modules/progress/quiz.util.ts)
- **描述**: 题目选项使用硬编码的 `charPool`、`pinyinPool`、`wordPool` 作为占位干扰项。代码注释已标注"真实词库接入后替换"。
- **建议**: 建立 `word_bank` 数据库表存储字/词/拼音/组词/例句，供题目生成和字词详情使用。

#### 问题 S-3：`submitQuiz()` 重试计数存在并发竞态
- **严重程度**: 中
- **位置**: [progress.service.ts](file:///d:/work/work/code/testsuit/公司/项目/酷酷儿童故事/server/src/modules/progress/progress.service.ts#L124-L128)
- **描述**: 重试次数的检查（`row.retryUsed < 1`）和递增（`row.retryUsed += 1`）分两次 `save` 操作，在并发请求下可能允许超过 1 次重试。
- **建议**: 使用数据库行级锁或原子 UPDATE 语句：`UPDATE learning_progress SET retry_used = retry_used + 1 WHERE child_id = $1 AND word_id = $2 AND retry_used < 1 RETURNING retry_used`。

#### 问题 S-4：`comprehensiveAuto()` 选取候选字无随机性
- **严重程度**: 低
- **位置**: [progress.service.ts](file:///d:/work/work/code/testsuit/公司/项目/酷酷儿童故事/server/src/modules/progress/progress.service.ts#L143-L147)
- **描述**: 使用 `order: { updatedAt: 'ASC' }` + `take: 10` 选取候选字，每次都取同样的 10 个字，无法覆盖所有好朋友等级的字词。
- **建议**: 增加随机排序，如 `order: { updatedAt: 'ASC' }` 改为使用 `ORDER BY RANDOM()` 或应用层随机打乱。

#### 问题 S-5：`parent.service.ts` 本周统计逻辑有误
- **严重程度**: 高
- **位置**: [parent.service.ts](file:///d:/work/work/code/testsuit/公司/项目/酷酷儿童故事/server/src/modules/parent/parent.service.ts#L50-L61)
- **描述**: `weekly()` 方法统计本周新增时，使用 `updatedAt: MoreThan(weekAgo)` 筛选所有本周更新的记录，然后统计 `currentStage >= 1/2/3` 的数量。这会把**本周之前就已达到该等级**的字词也计入"本周新增"，导致数据虚高。
- **建议**: 应该只统计本周**新达到**某等级的字词，需要记录等级变更时间戳或比较 `updatedAt` 与等级变更的对应关系。

#### 问题 S-6：`admin.service.ts` 需确认密码脚本存在
- **严重程度**: 低
- **位置**: [admin.service.ts](file:///d:/work/work/code/testsuit/公司/项目/酷酷儿童故事/server/src/modules/admin/admin.service.ts)
- **描述**: `package.json` 中定义了 `admin:hash-password` 脚本，但未确认 `scripts/generate-admin-password.cjs` 是否存在。
- **建议**: 验证脚本存在并确保其生成 scrypt 哈希格式与 `admin.service.ts` 中的验证逻辑一致。

#### 问题 S-7：测试覆盖率不足
- **严重程度**: 中
- **描述**: 当前仅有 5 个 spec 文件（rate-limit.guard、environment.validation、orders.service、quiz.util、child-ownership.service），核心业务模块（progress、auth、billing、history）缺少单元测试。

### 4.2 代码具体问题

#### 问题 M-1：缺少 React 错误边界
- **严重程度**: 中
- **描述**: 项目中未定义任何 Error Boundary 组件，页面级组件渲染错误会导致整个应用白屏。
- **建议**: 在 `components/` 下创建 `ErrorBoundary` 组件，在 `app.tsx` 中包裹顶层。

#### 问题 M-2：`api.ts` 的 `loginRedirecting` 存在状态泄漏
- **严重程度**: 低
- **位置**: [api.ts](file:///d:/work/work/code/testsuit/公司/项目/酷酷儿童故事/miniapp/src/services/api.ts#L16-L51)
- **描述**: `loginRedirecting` 是模块级变量，如果多个请求同时 401，只有一个会触发跳转，其他请求会静默失败。
- **建议**: 当前实现基本可接受，但建议在 `loginRedirecting` 重置后，让等待的请求返回明确的"登录已过期"错误而非静默失败。

#### 问题 M-3：`useDidShow` 中 API 调用缺少清理
- **严重程度**: 低
- **位置**: 多个页面（如 [story/index/index.tsx](file:///d:/work/work/code/testsuit/公司/项目/酷酷儿童故事/miniapp/src/pages/story/index/index.tsx#L55-L62)）
- **描述**: `useDidShow` 中发起 API 请求，但组件卸载时未取消请求，可能导致对已卸载组件的 setState 调用。
- **建议**: 使用 AbortController 或标志位在组件卸载时取消请求。

#### 问题 M-4：`indexLoader.ts` 缺少重试机制
- **严重程度**: 中
- **描述**: 索引加载失败时直接抛出错误，没有自动重试或降级策略。在网络不稳定环境下，用户可能频繁看到加载失败。
- **建议**: 增加指数退避重试（最多 3 次），失败后展示"加载失败，点击重试"。

#### 问题 M-5：`MiniPlayer` 组件功能过于精简
- **严重程度**: 低
- **位置**: [MiniPlayer](file:///d:/work/work/code/testsuit/公司/项目/酷酷儿童故事/miniapp/src/components/MiniPlayer/index.tsx)
- **描述**: 仅 52 行代码，缺少播放进度条、标题滚动、关闭按钮等基础交互。
- **建议**: 按 UI 设计稿补齐迷你播放栏的完整交互。

#### 问题 M-6：成长首页统计逻辑与后端不匹配
- **严重程度**: 中
- **位置**: [growth/index/index.tsx](file:///d:/work/work/code/testsuit/公司/项目/酷酷儿童故事/miniapp/src/pages/growth/index/index.tsx#L40-L44)
- **描述**: 前端通过 `total = learned + friends + mastered` 计算总数，但 `learned` 和 `friends` 在后端 summary 中是层级覆盖统计（`currentStage >= 1` 包含 `>= 2` 和 `>= 3`），相加会导致重复计数。
- **建议**: 前端直接使用后端返回的 `total_words_learned` 作为总数，不要自行相加。

#### 问题 M-7：缺少离线缓存策略
- **严重程度**: 低（P1 功能）
- **描述**: 文档中离线下载列为 P1 功能，但代码中没有任何离线缓存实现（Service Worker、本地文件缓存等）。
- **建议**: 在 P1 阶段实现时，使用 Taro 的文件系统 API 缓存音频和索引。
