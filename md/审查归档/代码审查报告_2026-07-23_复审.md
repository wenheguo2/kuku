## 二、新问题 / 仍需关注

### P1（高）— 凭证硬编码进源码

1. **SSH 明文弱口令**　`脚本/common.py:57`
   ```python
   REMOTE_PASS = "123456"
   ```
   远程机器 `172.30.10.30` 的 SSH 密码以明文写死，且为弱口令。

2. **MiniMax 长期账号 JWT 写死在源码**　`脚本/batch_songs.py:132`
   ```python
   "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJleHAiOjE3ODYyNTgzODcs..."
   ```
   该 token 为 MiniMax 音乐生成服务的长期账号凭证，直接提交进仓库。
   - 注：解码 `exp=1786258387` ≈ 2026-06，**当前看起来已过期**，但一旦被续期/复用即可能被冒用产生费用与消耗配额；且凭证本不应入仓。

3. 上述密码/ token 被 `fetch_lrc_from_remote.py:43`、`transfer_songs_to_remote.py:112` 用于 `ssh.connect(... password=REMOTE_PASS)` 登录。

**建议**：立即将 `REMOTE_PASS`、`MiniMax token` 改为环境变量 / 密钥管理；从 git 历史中清除并轮换 token、改 SSH 密钥登录；`common.py` 弱口令立即更改。

### P2（中）

4. **SSH 主机密钥校验被关闭（中间人风险）**　`fetch_lrc_from_remote.py:42` / `transfer_songs_to_remote.py`
   ```python
   ssh.set_missing_host_key_policy(paramiko.AutoAddPolicy())
   ```
   配合密码登录，局域网/中间人可劫持会话。
   **建议**：改 `RejectPolicy` + 维护 `known_hosts`，或改用密钥认证。

5. **命令注入隐患（`shell=True` 拼接 prompt）**　`脚本/11_generate_song_covers.py:107,123`、`脚本/10_generate_history_story_covers.py:101,118`
   ```python
   cmd = (f'"{DREAMINA}" ... --prompt="{prompt}" ...')
   proc = subprocess.run(cmd, shell=True, ...)
   ```
   `prompt` 直接拼入 shell 命令。若故事/角色名含 `"`、`;$()`、反引号等，会破坏命令或注入。当前输入为开发者可信内容，外暴露面低，但属典型代码异味。
   **建议**：`shell=False`，改为参数列表 `subprocess.run([DREAMINA, "text2image", "--prompt", prompt, ...])`。

6. **“仅 1 次重试”上限未由服务端强制（逻辑漏洞）**　`server/src/modules/progress/progress.service.ts`
   - `getQuiz`（约 :91）每次调用都把 `retryUsed` 重置为 0：`update({childId, wordId}, { retryUsed: 0, lastTestFailed: false })`。
   - `submitQuiz`（约:124）以 `row.retryUsed < 1` 判定可重试，并 `retryUsed: row.retryUsed + 1`。
   - 结果：用户可 `getQuiz → 答错 → 再 getQuiz`（状态被重置）→ 再答，循环直至答对。**PRD ED-028「仅 1 次重试」未真正生效**，挑战完整性可由客户端反复刷新绕过。
   **建议**：重试计数绑定到“本次挑战实例（test_id）”而非按 wordId 持久态；或仅在确属“重学该词”的显式动作下才重置。

7. **微信 mock 登录与 admin 密码 dev 分支**　`server/src/modules/auth/auth.service.ts`、`admin.service.ts:88-102`
   - `allowMockLogin` 默认 `!isRelease`，release 模式默认 false（良好）；但 `verifyPassword` dev 分支使用 `===` 比较，存在响应时间侧信道（仅 dev 生效）。
   **建议**：release 构建完全移除 dev 分支；保持现状亦可接受。

### P3（低 / 建议）

8. **静态托管缓存策略单一**　`server/src/main.ts:33`
   `useStaticAssets('production', { maxAge: 86400000 })` 对 JSON 索引与音频统一 24h 缓存。内容更新后客户端最长 24h 读到旧索引；音频本应更长缓存。建议区分“内容 JSON（短缓存/带版本号）”与“媒体（长缓存）”策略，并避免误暴露 production 目录下非预期文件。

9. **Admin 登录无按账户锁定**　`RateLimitGuard` 对未登录接口仅按 IP 限流。`POST /admin/auth/login` 无失败计数/锁定时长，弱口令 + 多来源 IP 可爆破。建议增加按账户失败计数与临时锁定。

10. **综合挑战并发无事务/行锁**　`submitComprehensive` / `comprehensiveManualStart` 未加锁，同一儿童并发提交可能竞态更新 stage（低概率）。

11. **quiz 占位实现**　`server/src/modules/progress/quiz.util.ts`
   选择题拼音 `correct='pīn'` 为占位常量，q1 干扰项来自固定 `charPool`，与具体字词无关。属占位实现，上线前需替换为真实内容，否则测评形同虚设。

12. **`deleteAccount` 依赖显式枚举删除表，schema 缺级联**　`server/src/db/schema.sql`
   `child_profiles`、`favorites`、`events`、`memberships`、`orders` 引用 `users`/`child_profiles` 时**未加 `ON DELETE CASCADE`**（如 `child_profiles.user_id` 第 37 行）。当前 `deleteAccount` 按依赖顺序显式删除各表因而正确；但若后续新增引用 `users`/`child_profiles` 的表而未设级联、也未加入删除列表，会触发外键失败。建议为从属表补 `ON DELETE CASCADE`，让 `deleteAccount` 仅删 `users`/`child_profiles`，降低维护遗漏风险。

13. **前端 SVG 拼接**　`miniapp/src/components/Icon/index.tsx:56`
   `PATHS[name]` 拼入 SVG data URI。`PATHS` 为固定可信表、且 data URI 不执行脚本，风险极低；保持 `PATHS` 不被外部输入污染即可。
