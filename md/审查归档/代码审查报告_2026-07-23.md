## 二、新发现问题清单

### M 级（建议下一迭代修复）

#### M-1 普通挑战"1 次重试"上限在服务端不可强制执行（PRD ED-028 失守）
- 位置：`server/src/modules/progress/progress.service.ts` getQuiz（约 L91）+ `miniapp/src/pages/growth/challenge/index.tsx`（约 L70）
- 现象：`getQuiz` 每次取题都执行 `update({retryUsed: 0, lastTestFailed: false})`；而小程序"再试一次"按钮直接调 `loadQuiz()` 重新 GET 取题 → 服务端每次都把重试计数清零 → 客户端可无限重试，"仅 1 次重试"仅是前端按钮约束。
- 跨流程副作用：md/11 §5.7 复习流程也复用 `GET /test/quiz` 取 test_id → 家长发起复习会顺带重置孩子的挑战重试状态。
- 建议：将 retryUsed 重置时机与"新挑战会话"绑定（如仅在上次挑战已判定通过/失败终态后重置），或为复习流程提供独立取题接口/参数；重试取题时服务端应 `retryUsed+1` 并在超限时拒绝。

#### M-2 GET /test/quiz 的 subject Query 参数无校验 → 500 而非 400
- 位置：`server/src/modules/progress/test.controller.ts`（约 L50-60）
- 现象：`@Query('subject') subject: Subject` 仅类型标注，无 `IsIn(['识字','英语','拼音'])` 校验；非法值向下传至 `getOrCreate` 写库时撞 `schema.sql` 的 `CHECK (subject IN ('识字','英语','拼音'))` 约束，返回 500。
- 建议：DTO 层加 `@IsIn` 白名单校验，非法入参以 400 拒绝。

#### M-3 PUT /user/profile 无长度/格式校验 → 超长入参 500
- 位置：`server/src/modules/auth/user.controller.ts` UpdateProfileDto（约 L22-25）
- 现象：nickname / avatar_url 仅 `@IsString()`；DB 为 varchar(64) / varchar(512)，超长写入触发 DB 错误返回 500。
- 建议：补 `@MaxLength(64)` / `@MaxLength(512)`，avatar_url 可加 `@IsUrl` 或协议白名单。

#### M-4 故事播放器页面卸载后自动续播断链 + 迷你栏状态残留
- 位置：`miniapp/src/pages/story/player/index.tsx`（约 L98-101）
- 现象：页面卸载时 `offEnded()` 移除续播回调 → 用户返回上级页后，后台音频播完不会自动续播队列下一篇（与 `requiredBackgroundModes:['audio']` 的后台播放预期矛盾）；且 `playerStore.isPlaying` 残留 true，MiniPlayer 显示"播放中"与实际不符。
- 建议：将"播完续播下一篇 + 同步 store 状态"的 onEnded 逻辑收敛到 `audioPlayer` 服务/`playerStore` 全局注册，页面只挂载 UI 层回调。

#### M-5 member / challenge 页 Zustand 全量订阅（与历史整改口径不一致）
- 位置：`miniapp/src/pages/common/member/index.tsx`（约 L21-28）、`miniapp/src/pages/growth/challenge/index.tsx`（约 L22）
- 现象：`const {…} = useUserStore()` 无 selector 全量订阅，store 任意字段变化都会重渲染整页；历史整改（M-10/11/12）已将其他页面统一为 selector 订阅，此两页遗漏。
- 建议：改为 `useUserStore(s => s.xxx)` 选择性订阅，与 MiniPlayer 等已整改组件对齐。

### L 级（择机修复 / 记录在案）
