# 01 · 环境准备与安装

> 本篇：申请云服务器 → 装齐所有运行环境（Node / PostgreSQL / Nginx / pm2，可选 Redis）。
> 命令以 **Ubuntu 22.04 LTS** 为例（云厂商最通用）。CentOS/AlmaLinux 把 `apt` 换成 `dnf`、包名略有差异。
> 全程用 `root` 或有 `sudo` 的账号执行。

---

## 1. 云服务器选型

| 方案 | 规格 | 系统盘 | 数据盘 | 适用 |
|---|---|---|---|---|
| **A：对象存储+CDN**（推荐） | 2 核 4G | 40–60 GB | 不需要 | 正式上线（内容在 COS/CDN，服务器只跑 API+DB） |
| **B：单机大盘直服** | 2 核 4G（4 核 8G 更稳） | 40 GB | **≥ 600 GB**（放 450GB 内容+余量） | 内测/演示 |

- **地域**：面向国内用户选**国内地域**（如上海/北京/广州），且**必须完成 ICP 备案**（见 `md/21`）。
- **操作系统镜像**：Ubuntu 22.04 LTS（本篇命令基准）。
- **公网 IP / 带宽**：方案 A 带宽 3–5Mbps 够（大文件走 CDN）；方案 B 需较大带宽（音频直连服务器）。

### 1.1 安全组 / 防火墙端口
在云控制台「安全组」放行 + 服务器本地防火墙一致：

| 端口 | 用途 | 对外开放？ |
|---|---|---|
| 22 | SSH 登录 | 是（建议限制来源 IP） |
| 80 | HTTP（证书申请/跳转 HTTPS） | 是 |
| 443 | HTTPS（API + 静态方案B） | 是 |
| 3000 | NestJS | **否**（仅本机，Nginx 内部反代，切勿公网暴露） |
| 5432 | PostgreSQL | **否**（仅本机） |
| 6379 | Redis | **否**（仅本机） |

```bash
# Ubuntu ufw 示例（可选，云安全组已控可跳过）
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status
```

## 3. Node.js 20 LTS

后端运行、小程序构建都用 Node。服务器装 **Node 20 LTS**（`@types/node@20`，最稳）。

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v   # 期望 v20.x
npm -v
# 国内可选加速
npm config set registry https://registry.npmmirror.com
```

> 小程序**构建**也可在本地开发机做（见文档 04），不强制在服务器构建。服务器主要跑后端。

---

## 4. PostgreSQL 15

`schema.sql` 基线为 PostgreSQL 15。Ubuntu 22.04 默认源是 PG14，用官方 PGDG 源装 **15**：

```bash
sudo apt install -y postgresql-common
sudo /usr/share/postgresql-common/pgdg/apt.postgresql.org.sh -y   # 自动加 PGDG 源
sudo apt install -y postgresql-15
sudo systemctl enable --now postgresql
psql --version   # 期望 psql (PostgreSQL) 15.x
sudo -u postgres psql -c "SELECT version();"
```

> 建库、建角色、执行 `schema.sql` 在**文档 02** 做。这里只装引擎。

## 5. Redis（可选）

后端限流/测试态用 Redis；**单机单实例可不装**（代码会自动回退进程内存，启动日志显示 `Redis 不可用，TestStore 回退进程内 Map（单实例可用）`）。要更稳或将来多实例则装：

```bash
sudo apt install -y redis-server
sudo systemctl enable --now redis-server
redis-cli ping   # 期望 PONG
```

装了就在 `.env` 配 `REDIS_HOST=localhost` / `REDIS_PORT=6379`（文档 02）。不装则留默认，功能不受影响。

## 7. pm2（Node 进程守护）

```bash

pm2 -v
```

> 用法（启动后端、开机自启）在**文档 02 §5**。

## 8. （方案 A）对象存储上传工具

方案 A 要把 `production/` 传到 COS/OSS，**在存放内容母本的机器上**装上传工具（通常是你的 Windows 开发机，见文档 03 §3.2；若内容已在服务器则装到服务器）：

- **腾讯云 COS**：图形工具 **COSBrowser**（最省心，拖拽整目录+断点续传），或命令行 **coscli**。
- **阿里云 OSS**：图形工具 **ossbrowser**，或命令行 **ossutil**。

> ⚠️ 命令行工具的下载地址随版本更新，**请到对应云厂商「对象存储 → 工具下载/迁移工具」官方文档取对应系统（Windows/Linux）的最新版**，勿照搬网上旧链接。装好后配置一次密钥/地域/桶：
> - coscli：`coscli config init`
> - ossutil：`ossutil config`
>
> 批量上传命令见**文档 03 §3.2**（含 Windows 与 Linux 两种写法）。
