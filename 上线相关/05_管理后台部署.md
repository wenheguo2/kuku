# 05 · 管理后台部署（可选，建议）

> 项目里有一个独立的 **管理后台 Web**（`admin/`，Vue 3 + Element Plus + Vite），用于内容管理/数据统计，调用后端 `/api/v1/admin/*`。
> **小程序不依赖它也能正常上线使用**；但要看运营数据/管理，建议一并部署。本篇给出完整、可照抄的步骤。

前置：文档 02 后端已跑通（含 `ADMIN_USERNAME` 与 `ADMIN_PASSWORD_SCRYPT`、`ADMIN_JWT_SECRET`），Nginx/证书机制同文档 03。

---

## 1. 它是什么 / 怎么连后端

- 代码：`项目/酷酷儿童故事/admin/`，构建工具 Vite（`npm run build` → `vue-tsc -b && vite build` → 产物在 `admin/dist/`）。
- API 地址：源码 `src/services`（axios）用 `import.meta.env.VITE_API_BASE_URL`，并在其后拼 `/api/v1`：
  - 即 **`VITE_API_BASE_URL` 只填到域名**（如 `https://api.你的域名`，**不要**带 `/api/v1`）。
  - 留空则用相对路径 `/api/v1`（仅当后台与 API 同源时才行）。
- 登录：用后端 `.env` 里的 `ADMIN_USERNAME` + 你在文档 02 §3.1 用 `KUKU_ADMIN_PASSWORD` 生成 scrypt 时设的**明文口令**（scrypt 是它的哈希，登录时输原始明文）。
- 开发期：Vite 自带 `/api`、`/static` 代理到 `localhost:3000`（`vite.config.ts`），仅本地联调用；生产不经它，靠下面的域名+CORS。

---

## 2. 构建（在本地开发机，Windows）

后台是独立域名 `admin.你的域名`，跨域访问 `api.你的域名`，用环境变量注入 API 域名：

```powershell
cd 项目\酷酷儿童故事\admin
npm ci
# 方式一（推荐，可复现）：建 admin\.env.production 文件，写一行：
#   VITE_API_BASE_URL=https://api.你的域名
npm run build          # 产物在 admin\dist\

# 方式二（临时）：当次注入
$env:VITE_API_BASE_URL="https://api.你的域名"; npm run build
```

> 校验：`Select-String -Path dist\assets\*.js -Pattern "api.你的域名" | Select-Object -First 1` 应能命中，说明域名已编译进产物。

把 `admin/dist/` 传到服务器（如 `/opt/kuku/admin-dist/`；内容小，scp/WinSCP 均可）。

---

## 3. 后端放行跨域（重要，否则后台请求被浏览器拦）

后台在 `admin.你的域名`、API 在 `api.你的域名`，属跨域。后端生产（模式2，`NODE_ENV=production`）的 CORS 只放行 `CORS_ORIGINS` 列表：

- 编辑 `/opt/kuku/server/.env`，加上后台域名（多个逗号分隔）：
  ```ini
  CORS_ORIGINS=https://admin.你的域名
  ```
- `pm2 restart kuku-api`。
- 模式1（`NODE_ENV=development`）时后端 CORS 默认放行所有来源，无需配；但上线到模式2**务必**补上，否则后台白屏/请求失败。

> 想省掉 CORS：也可把后台挂到与 API **同源**的子路径（如 `https://api.你的域名/admin/`），但需给 Vite 设 `base: '/admin/'` 重新构建。多数情况用独立 `admin.` 子域 + CORS 更直接，本篇按此。

---

## 4. Nginx 服务后台静态 + HTTPS

先把 `admin.你的域名` DNS A 记录解析到服务器 IP。新增 Nginx server 块（可并入 `/etc/nginx/sites-available/kuku.conf`）：

```nginx
server {
    server_name admin.你的域名;
    root /opt/kuku/admin-dist;
    index index.html;

    # Vue Router history 模式需回退到 index.html（hash 模式也不受影响）
    location / {
        try_files $uri $uri/ /index.html;
    }
    listen 80;   # 下一步 certbot 会补 443
}
```

申请证书并重载：
```bash
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d admin.你的域名     # 后台是登录入口，必须 HTTPS
```

---

## 5. 验证 ✅

- [ ] 浏览器打开 `https://admin.你的域名`，页面正常加载（非白屏）
- [ ] 用 `ADMIN_USERNAME` + 明文口令登录成功（走 `/api/v1/admin/auth/login`）
- [ ] 能看到统计/管理数据（`/api/v1/admin/stats` 正常返回，无 CORS 报错）
- [ ] 浏览器控制台无 `CORS`/`Mixed Content` 报错（全 HTTPS、CORS_ORIGINS 已含后台域名）

排错：
- **白屏 + 控制台 CORS 报错** → 后端 `.env` 的 `CORS_ORIGINS` 没含 `https://admin.你的域名`，或没 `pm2 restart`。
- **登录 401** → 口令错（scrypt 对应的是你设的明文），或 `ADMIN_JWT_SECRET` 未配（模式2 必配且 ≥32 位、≠JWT_SECRET）。
- **接口 404/连不上** → `VITE_API_BASE_URL` 填错（应为 `https://api.你的域名`，不带 `/api/v1`）。

---

_可选章节结束。不部署后台不影响小程序上线；部署了则多一个运营管理入口。_
