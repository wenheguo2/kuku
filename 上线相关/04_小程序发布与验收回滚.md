# 04 · 小程序发布与验收回滚

> 本篇：用真实 AppID + 生产域名构建小程序 → 配微信服务器域名白名单 → 上传提审发布 → 端到端验收 → 备份/回滚。
> 前置：文档 02/03 完成，`https://api.你的域名/api/v1/health` 与静态域名均可访问（HTTPS）。
> 后端渠道边界：必须 `WEAPP_AUTH_ENABLED=true`；`APP_AUTH_ENABLED` 是否开启与本次小程序发布无关。真实支付未接入前保持 `WECHAT_PAY_ENABLED=false`。

---

## 1. 准备真实 AppID

小程序构建/上传要用**真实 AppID**（当前仓库是占位 `touristappid`）：

1. 微信公众平台（mp.weixin.qq.com）→ 注册/登录**小程序**账号，拿到 **AppID** 与 **AppSecret**。
   - AppSecret 填到后端 `.env` 的 `WX_SECRET`（文档 02 §3.2）。
   - ⚠️ 此 **AppID 必须与后端 `.env` 的 `WX_APPID` 完全一致**，否则 `Taro.login()` 拿到的 code 在 code2session 校验失败、登录不了。
2. 改 `miniapp/project.config.json` 的 `appid`：
   ```json
   "appid": "wx你的真实AppID"
   ```
   （构建时 Taro 会把此文件拷到 `dist/`，开发者工具打开的是 `dist/`——所以**改完 appid 必须重新走 §3 构建**，`dist/project.config.json` 才会更新。构建时另用 `TARO_APP_APPID` 做发布门禁校验，见 §3。）

---

## 2. 配置微信「服务器域名」白名单（不配会请求全失败）

微信公众平台 → **开发管理 → 开发设置 → 服务器域名**，把下列域名加入白名单（**必须 HTTPS 且已备案**）：

| 类型 | 填什么 | 用途 |
|---|---|---|
| **request 合法域名** | `https://api.你的域名` | 业务 API |
| **downloadFile 合法域名** | 方案A：`https://cdn.你的域名`　方案B：`https://你的域名` | 封面图片、音频下载 |

- 一个月内修改次数有限，尽量一次配好。
- `socket / uploadFile / 业务域名` 本项目不需要，留空。
- 配置后需在开发者工具「详情 → 本地设置」勾选/取消对应校验做真机验证。

---

## 3. 生产构建小程序

在**本地开发机**（Windows）的 `miniapp/` 目录执行。构建时通过环境变量注入真实域名/AppID，`config/index.ts` 的发布门禁会校验（有 `example.com`、`touristappid`、`useMock`、非 https、协议未定稿都会**直接报错**）。

### 3.1 PowerShell（Windows）——正式发布构建
```powershell
cd 项目\酷酷儿童故事\miniapp
$env:TARO_APP_RELEASE       = "true"
$env:TARO_APP_API_BASE_URL  = "https://api.你的域名/api/v1"
$env:TARO_APP_STATIC_BASE_URL = "https://cdn.你的域名"   # 方案B填 https://你的域名/static
$env:TARO_APP_APPID         = "wx你的真实AppID"
$env:TARO_APP_USE_MOCK      = "false"
$env:TARO_APP_AGREEMENTS_FINAL = "true"                  # 需法务协议定稿；见 §3.3
npx taro build --type weapp
```

构建产物在 `miniapp/dist/`。

### 3.2 校验注入是否正确
```powershell
# dist 里应能看到真实域名，且不含 example.com / touristappid
Select-String -Path dist\common.js -Pattern "api.你的域名|cdn.你的域名" | Select-Object -First 2
```

### 3.3 关于 `TARO_APP_AGREEMENTS_FINAL` 与协议
- 门禁要求发布版协议为**法务定稿**（`TARO_APP_AGREEMENTS_FINAL=true`，且后端三份协议版本号不含 `draft`）。协议定稿前，公开发布会被门禁/微信审核拦截。
- 若只是**内部体验版**联调（不公开），可暂不设 `TARO_APP_RELEASE=true`，但仍需设 `TARO_APP_API_BASE_URL / TARO_APP_STATIC_BASE_URL / TARO_APP_APPID` 为真实值（否则默认指向 `example.com` 占位，无法联调）。
- **正式对外发布前，务必协议定稿并全量走 §3.1 的 release 构建。**

## 4. 上传 → 提审 → 发布

1. 用微信开发者工具打开 `miniapp/dist`（**直开 dist**，详见 `md/22-微信开发者工具使用指南.md`）。
2. 工具右上角「**上传**」→ 填版本号与备注 → 上传为**开发版**。
3. 公众平台 → 版本管理：把上传的版本设为「**体验版**」，用体验成员真机全流程自测（见 §5）。
4. 自测通过 → 「**提交审核**」，填类目、页面截图、隐私说明等（提审类目/资质/隐私见 `md/15-上线合规与资质checklist`；真机/登录/支付等“什么还没测”风险清单见 `md/23-小程序测试与验收报告`）。
5. 审核通过 → 「**发布**」，正式上线。

> 提审注意：需在小程序后台配置**用户隐私保护指引**（收集头像/昵称等），否则审核不过；类目需与「儿童/教育/内容」相符。

## 5. 端到端验收清单（真机体验版逐项点检）

> 全绿 = 上线完成、可正常使用。任一失败先修再发布。

**登录与账号**
- [ ] 微信授权登录成功（真实 openid，非 mock），个人信息正常
- [ ] 新用户注册后有 **3 天免费期**（会员页/家长中心显示「还剩 N 天」）

**播放（核心）**
- [ ] 故事：首页今日推荐、章回推荐、为你推荐、学科九宫格封面都能显示（走 CDN/静态域名）
- [ ] 点开一个故事能正常播放 MP3（音频域名在 downloadFile 白名单内）
- [ ] 歌曲页同上；播放器上一首/下一首正常
- [ ] **免费专区列表循环只在池内**，播完不串到池外内容
- [ ] **收藏里点下一首只在收藏内**，不串到原目录

**收藏/历史/会员**
- [ ] 收藏、取消收藏、历史记录、清空历史均正常
- [ ] 会员页文案正确；点「确认开通」：模式1 走 stub 提示、模式2 走真实支付
- [ ] 会员/赠送到期时间**累加**展示正确（买会员不覆盖赠送天数）

**拉新**
- [ ] 分享带邀请参数；被邀请新用户注册后，邀请者免费期 **+3 天**（多次可累加，有上限）

**性能/兼容**
- [ ] 首屏加载顺畅（gzip 生效：索引传输显著变小）
- [ ] 列表滚动时封面懒加载、无裂图
- [ ] 夜间/日间模式、返回首页后迷你播放栏仍在

## 6. 备份 · 监控 · 回滚

### 6.1 每日数据库备份（crontab）
```bash
sudo crontab -e
# 每天 03:30 备份，保留最近 14 天
30 3 * * * sudo -u postgres pg_dump -Fc kuku_stories > /opt/kuku/backup/kuku_$(date +\%F).dump && find /opt/kuku/backup -name 'kuku_*.dump' -mtime +14 -delete
```

### 6.2 监控
```bash
pm2 status            # 进程存活
pm2 logs kuku-api     # 实时日志
pm2 monit             # 资源占用
pm2 install pm2-logrotate   # 日志自动轮转，防止 pm2 日志把磁盘写满
# 建议：云监控对 https://api.你的域名/api/v1/health 做拨测告警
```

### 6.3 回滚
- **后端**：保留上一个可用 `dist/`（或上一个 git tag）。回滚时替换 `dist/` → `pm2 restart kuku-api` → 查 health。
- **数据库**：误操作用最近备份 `pg_restore -d kuku_stories --clean 最近.dump`（先停应用）。
- **小程序**：公众平台 → 版本管理 → 「**版本回退**」到上一线上版本（分钟级生效）。
- **静态资源**：方案A 在 CDN 刷新/回滚对象版本；方案B 保留 `production` 上一次快照。
