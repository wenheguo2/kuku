# 02 · 数据库与后端部署

> 本篇：建库建表（12 张表）→ 部署 NestJS 后端 → 写生产 `.env` → 构建 → pm2 常驻 → 健康检查。
> 前置：文档 01 已装好 Node 20 / PostgreSQL 15 / pm2。

约定路径（可自定，本篇以此为例）：
- 后端代码：`/opt/kuku/server`
- 静态内容（方案 B 才放服务器）：`/opt/kuku/production`

---

## 1. 数据库：建角色、建库、建表

### 1.1 建应用角色与数据库
用超级用户 `postgres` 执行。**生产密码务必换成强随机密码**（发布门禁禁止用默认 `kuku2026`）：

```bash
sudo -u postgres psql
```
```sql
-- 应用连接用的角色（先建，schema.sql 结尾会 GRANT 给它）
CREATE ROLE kuku_app LOGIN PASSWORD '换成你的强密码_如R7xK...';
-- 业务库
CREATE DATABASE kuku_stories OWNER postgres ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0;
-- 让 kuku_app 能用 public schema（PG15 默认收紧了 public 权限）
\c kuku_stories
GRANT ALL ON SCHEMA public TO kuku_app;
\q
```

### 1.2 执行 schema.sql 建 12 张表
`schema.sql` 用 `CREATE TABLE IF NOT EXISTS` + 结尾 `GRANT ... TO kuku_app`，**用 postgres 执行**（表属主为 postgres，kuku_app 获全部操作权限；这与开发期一致）：

```bash
sudo -u postgres psql -d kuku_stories -f /opt/kuku/server/src/db/schema.sql
```

> `schema.sql` 已含用户表的 `free_until / invited_by / referral_count`（免费期/拉新字段），全新库一次建成，无需再补 ALTER。

### 1.3 验证 12 张表
```bash
sudo -u postgres psql -d kuku_stories -c "\dt"
```
应看到 **12 张表**：`users, consent_records, child_profiles, favorites, play_history, learning_progress, comprehensive_tests, child_achievements, parent_settings, events, memberships, orders`。

再验证 kuku_app 能带密码登录并读表：
```bash
psql "postgresql://kuku_app:你的强密码@127.0.0.1:5432/kuku_stories" -c "\dt" -c "SELECT count(*) FROM users;"
```
> 若报认证失败：检查 `/etc/postgresql/15/main/pg_hba.conf` 中 `host all all 127.0.0.1/32 scram-sha-256`（默认即如此），改动后 `sudo systemctl reload postgresql`。

### 1.4 关于以后改表结构（重要）
表属主是 postgres，`kuku_app` 只有数据操作权限、**无 DDL 权限**。以后要 `ALTER TABLE`（加字段等）必须用 `sudo -u postgres psql`（与开发期同一约束）。应用 `synchronize=false`，绝不自动改表。

### 1.5 数据库备份（上线前先建立习惯）
```bash
# 手动备份
sudo -u postgres pg_dump -Fc kuku_stories > /opt/kuku/backup/kuku_$(date +%F).dump
# 恢复（灾备时）
sudo -u postgres pg_restore -d kuku_stories --clean /opt/kuku/backup/xxx.dump
```
建议加 crontab 每日备份（见文档 04 §5）。

## 2. 后端代码上线

### 2.1 放代码
只需把仓库的 **`server/` 目录**放到服务器（**不要**把 450GB 的 `production/` 一起塞系统盘；静态内容见文档 03）：

```bash
sudo mkdir -p /opt/kuku && cd /opt/kuku
# 方式一：git（git 操作由你自己做，仓库地址替换为你的）
git clone <你的仓库地址> repo && cp -r repo/项目/酷酷儿童故事/server /opt/kuku/server
# 方式二：本地打包上传（在开发机）
#   仅打包 server（排除 node_modules）：tar --exclude=node_modules -czf server.tgz server/
#   scp server.tgz 到服务器后 tar -xzf server.tgz -C /opt/kuku/
cd /opt/kuku/server
```

### 2.2 装依赖
```bash
cd /opt/kuku/server
npm ci        # 按 package-lock 精确安装；无 lock 用 npm install
```

## 3. 生产 `.env`（逐项，二选一模式）

在 `/opt/kuku/server/.env` 新建。**先看清 §3.3 的两种模式**，再据此填 `NODE_ENV / ALLOW_PAYMENT_STUB / WXPAY_*`。

### 3.1 先生成两个强密钥与管理员口令
```bash
openssl rand -hex 32     # → 复制给 JWT_SECRET
openssl rand -hex 32     # → 复制给 ADMIN_JWT_SECRET（必须与 JWT_SECRET 不同）
# 生成管理后台口令哈希：脚本读取环境变量 KUKU_ADMIN_PASSWORD（≥12 位，非交互、无参数），打印整行结果
cd /opt/kuku/server
KUKU_ADMIN_PASSWORD='设一个≥12位的后台登录口令' npm run admin:hash-password
#  ↑ 输出形如：ADMIN_PASSWORD_SCRYPT=scrypt$<盐hex>$<哈希hex>
#    把这一整行原样复制，替换 .env 模板里的 ADMIN_PASSWORD_SCRYPT= 那行
```

### 3.2 `.env` 模板（复制后按注释替换）
```ini
# ---- 服务 ----
NODE_ENV=production            # 见 §3.3：卖会员=production；暂不卖会员=development
RELEASE_MODE=false
PORT=3000
API_PREFIX=api/v1
# 允许小程序请求来源；小程序无需 CORS，留空即可（浏览器端 H5 才需要）
CORS_ORIGINS=
# 静态资源根目录（相对 server/）。方案A(CDN)：指到一个空目录即可；方案B：指到内容目录
STATIC_ROOT=../production

# ---- PostgreSQL ----
DB_HOST=localhost
DB_PORT=5432
DB_NAME=kuku_stories
DB_USER=kuku_app
DB_PASSWORD=你在 1.1 设的强密码     # 禁止用 kuku2026

# ---- Redis（没装就留默认，功能自动回退）----
REDIS_HOST=localhost
REDIS_PORT=6379

# ---- JWT ----
JWT_SECRET=粘贴 openssl 生成的 64 位十六进制
JWT_EXPIRES_IN=7d

# ---- 管理后台 ----
ADMIN_USERNAME=admin
ADMIN_PASSWORD=                 # 生产留空，改用下面的 scrypt
ADMIN_PASSWORD_SCRYPT=粘贴 npm run admin:hash-password 的输出 scrypt$...$...
ADMIN_JWT_EXPIRES_IN=8h
ADMIN_JWT_SECRET=粘贴另一个 openssl 64 位（≠ JWT_SECRET）

# ---- 微信登录（正式用户必须 real）----
WX_LOGIN_MODE=real
ALLOW_MOCK_LOGIN=false
WX_APPID=你的小程序 AppID
WX_SECRET=你的小程序 AppSecret

# ---- 微信支付（见 §3.3）----
ALLOW_PAYMENT_STUB=true        # 模式1=true；模式2(卖会员)=false 且填下面两项
WXPAY_MCH_ID=
WXPAY_API_V3_KEY=

# ---- 协议版本（法务定稿后替换，模式2 不能含 draft）----
USER_AGREEMENT_VERSION=2026-07-draft
PRIVACY_VERSION=2026-07-draft
CHILDREN_PRIVACY_VERSION=2026-07-draft
```

### 3.3 两种模式（关键决策）
后端 `environment.validation.ts` 有发布门禁。`NODE_ENV=production` 或 `RELEASE_MODE=true` 会触发**完整校验**（必须真实微信支付、协议非 draft、禁 mock/stub 等）。当前**微信支付真实通道尚未实现**，因此：

**模式 1 · 先上线、内容可正常用、暂不真扣款（本轮推荐）**
- `NODE_ENV=development`（关键：不设为 production，避免触发必须支付的门禁）
- `RELEASE_MODE=false`、`WX_LOGIN_MODE=real` + 真实 `WX_APPID/WX_SECRET`（真实用户登录）
- `ALLOW_PAYMENT_STUB=true`、`WXPAY_*` 留空
- `ALLOW_MOCK_LOGIN=false`
- **仍然**填强 `JWT_SECRET` / `ADMIN_PASSWORD_SCRYPT` / `ADMIN_JWT_SECRET`（安全，别偷懒）
- 影响：登录、故事/歌曲/收藏/历史/免费区/会员到期展示全部真实可用；点「开通会员」走 stub 不真实扣款。
- 注意：此模式下后端会启用「开发期 webp→png 兼容中间件」（对 `/static` 封面按需转码）。**方案 A（客户端走 CDN、不访问后端 /static）下无影响**；方案 B 下真机本可直接解码 webp，此中间件仅带来少量 CPU 开销，可接受。

**模式 2 · 完全生产、卖会员**
- 先完成微信支付 v3 对接（开发任务，本文档范围外）
- `NODE_ENV=production`，填全 `WXPAY_MCH_ID/WXPAY_API_V3_KEY`，`ALLOW_PAYMENT_STUB=false`
- 三份协议版本换成法务定稿（不含 `draft`）
- 门禁会强制校验以上全部，缺一启动即失败（防呆）

> 无论哪种模式，`WX_LOGIN_MODE=real` 时都**必须**有 `WX_APPID/WX_SECRET`，否则启动失败。

### 3.4 方案 A 的空静态目录
方案 A（内容在 CDN，服务器不放 450GB）下，为避免 `STATIC_ROOT` 指向不存在目录，建一个空目录占位：
```bash
mkdir -p /opt/kuku/production
```
客户端静态请求都走 CDN，不打后端 `/static`，此目录空着即可。

## 5. pm2 常驻 + 开机自启

```bash
cd /opt/kuku/server
# 用 dist/main.js 启动，cwd 必须是 server 目录（ConfigModule 从 cwd 读 .env）
pm2 start dist/main.js --name kuku-api --cwd /opt/kuku/server
pm2 status                       # kuku-api 应为 online
pm2 logs kuku-api --lines 40     # 看启动日志，末尾应有 running at http://localhost:3000/api/v1

# 开机自启（按提示复制执行它输出的一条 sudo 命令）
pm2 startup
pm2 save
```

> 若启动即退出：`pm2 logs kuku-api` 看报错。最常见是**环境门禁失败**（缺密钥/协议 draft/DB 密码是默认值等），按 §3.3 修 `.env` 后 `pm2 restart kuku-api`。

## 6. 健康检查（本机）

```bash
curl http://127.0.0.1:3000/api/v1/health
```
期望返回（`code:0` + `db:true` 表示数据库连通）：
```json
{"code":0,"message":"ok","data":{"status":"ok","db":true,"time":"..."}}
```

- `db:false` → 检查 `.env` 的 `DB_*` 与 1.3 的连接串是否一致、PostgreSQL 是否运行。
- 连不上 3000 → `pm2 status` 看进程是否 online、`pm2 logs` 看报错。
