## 1. 系统架构总览

```
                        微信小程序（用户手机）
                               │  HTTPS
             ┌─────────────────┼──────────────────────┐
             │ (1) 业务 API                (2) 静态资源（索引/封面/音频）
             ▼                                          ▼
   https://api.你的域名/api/v1              https://cdn.你的域名/...
             │                                          │
      ┌──────┴───────┐                    ┌─────────────┴──────────────┐
      │  Nginx 反代   │                    │ 方案A: 对象存储COS + CDN    │
      │   (443→3000) │                    │ 方案B: 同机 Nginx 直服 /static │
      └──────┬───────┘                    └────────────────────────────┘
             ▼
      NestJS 后端 (pm2, :3000)
             │
      ┌──────┴───────┬──────────────┐
      ▼              ▼              ▼
  PostgreSQL 15   Redis(可选)   production/（本地静态，方案B时用）
  (12 张表)       (限流/多实例)
```

- **业务 API**：NestJS，端口 3000，全局前缀 `/api/v1`，由 Nginx 443 反代 + HTTPS。
- **静态资源**：索引 JSON、封面图、故事/歌曲 MP3。**内容体量约 450GB**（见下），是本次部署的最大难点，决定了架构选型。
- **数据库**：PostgreSQL 15，12 张表（用户/收藏/历史/进度/会员/订单等），`synchronize=false`，由 `schema.sql` 建表。
- **Redis**：可选。单机单实例可不装（限流/测试态会自动回退进程内存）；多实例或要限流持久化时需要。

## 2. 关键结论：内容体量与架构选型（务必先读）

实测 `production/` 静态内容规模：

| 目录 | 文件数 | 体积 | 说明 |
|---|---|---|---|
| `audio/` | 约 232 万 | **约 352 GB** | 故事/歌曲 MP3（含分段） |
| `generated_stories/` | 约 39 万 | **约 93 GB** | 按作品组织的音频与元数据 |
| `illustrations/` | 约 3.2 万 | 约 4 GB | 封面/插画（含 covers、场景图） |
| `index/` | 271 | 约 20 MB | 索引 JSON（首页/搜索/目录） |
| **合计** | — | **约 450 GB** | — |

> ⚠️ **这个体量放不进普通云服务器的系统盘**，也不能用 scp 从本地笔记本慢慢传。它直接决定：

### 方案 A（推荐，正式上线）：对象存储 + CDN
- 把 `production/` 全量传到**对象存储**（腾讯云 COS / 阿里云 OSS），前面挂 **CDN** 加速。
- 小程序静态地址 `staticBaseUrl` 指向 **CDN 域名**；NestJS 只跑 API，不背 450GB。
- 优点：容量无上限、全国加速快、服务器便宜（2C4G 即可）、稳定。
- 缺点：要开通 COS+CDN，首次上传耗时（走专用工具批量上传，见文档 03）。

### 方案 B（小规模/内测）：单机大盘直服
- 云服务器挂**≥600GB 数据盘**，`production/` 放上去，Nginx 直接服务 `/static`。
- 优点：简单、无额外服务。缺点：首屏慢、带宽受单机限制、不易扩展、迁移麻烦。

**结论**：正式对外上线用**方案 A**；仅内测/演示可用**方案 B**。文档 03 两套都给完整步骤。

> CDN 是什么？一句话：把你的静态文件（图片、音频）**复制缓存到全国各地的边缘节点**，用户就近下载，快且不占你服务器带宽。它**不替代**服务器，是配合服务器用的加速层。详见 `03_静态资源_CDN_Nginx_HTTPS.md §1`。

## 3. 上线前置凭据清单（没有这些无法真正上线）

后端 `environment.validation.ts` 与小程序 `config/index.ts` 都有**发布门禁**——生产环境缺少下列任一项将**直接启动失败 / 构建报错**（这是有意的防呆）。请提前准备：

| 凭据/资源 | 用途 | 从哪来 | 缺失后果 |
|---|---|---|---|
| **域名**（如 `你的域名.com`） | API 域名 + 静态/CDN 域名 | 域名注册商 | 无法配 HTTPS、无法上线 |
| **ICP 备案** | 中国大陆服务器/域名强制 | 云厂商备案系统（见 `md/21`） | 域名无法解析使用 |
| **HTTPS 证书** | 微信小程序强制 HTTPS | 云厂商免费证书 / certbot | 小程序无法请求 |
| **小程序 AppID + AppSecret** | 真实微信登录 | 微信公众平台 | 只能 mock 登录（假用户） |
| **微信支付商户号 `WXPAY_MCH_ID` + APIv3 密钥** | 会员付费 | 微信支付商户平台 | ⚠️ 见下方「支付说明」 |
| **JWT 密钥（≥32 位随机）** | 登录令牌签名 | 自行生成 | 生产启动失败 |
| **管理后台 scrypt 口令 + 独立 ADMIN_JWT_SECRET** | 后台登录 | `npm run admin:hash-password` 生成 | 生产启动失败 |
| **三份法务定稿协议版本号**（用户协议/隐私/儿童隐私，不含 `draft`） | 合规 | 法务定稿 | 生产启动失败 |

> 外部凭据的申请指引另见项目内 `开发文档/待办-外部凭据清单.md` 与 `md/21`（资质办理操作手册·个体户/ICP）、`md/17`（合规资质备案执行指南）、`md/15`（上线合规与资质checklist）。

### ⚠️ 支付说明（重要，务必知悉）
当前代码**微信支付真实通道尚未实现**（仅 stub）。而后端发布门禁规定：`NODE_ENV=production` 时**必须**配置 `WXPAY_MCH_ID`/`WXPAY_API_V3_KEY` 且**禁止** `ALLOW_PAYMENT_STUB`。这意味着二选一：

1. **先上线、暂不卖会员**：在服务器用 `RELEASE_MODE`/`NODE_ENV` 的「准生产」配置（真实微信登录 + 允许支付 stub），内容功能全部可用，会员购买按钮暂不接真实扣款。**这是本轮建议**（内容可正常使用，付费后续补）。
2. **要卖会员**：先完成微信支付 v3 对接（属开发任务，不在本部署文档范围），拿到商户号后再切 `NODE_ENV=production`。

文档 02 的 `.env` 配置会**同时给出两种模式的具体取值**，你按实际选择填。

## 4. 一页速览：从零到上线的 10 个步骤

1. 申请云服务器（方案A：2C4G+40G系统盘即可；方案B：另挂≥600G数据盘）与域名，完成 **ICP 备案**。 → 文档 01
2. 服务器装 **Node 20 LTS、PostgreSQL 15、Nginx、pm2、git**（可选 Redis）。 → 文档 01
3. 建数据库角色 `kuku_app`、建库 `kuku_stories`、执行 `schema.sql` 建 **12 张表**。 → 文档 02
4. 拉后端代码，`npm ci` → 写生产 `.env`（逐项）→ 生成 admin 口令 → `npm run build`。 → 文档 02
5. `pm2` 常驻后端，`curl /api/v1/health` 返回 `db:true`。 → 文档 02
6. 传静态内容：**方案A** 上传 COS 并配 CDN；**方案B** 放数据盘。 → 文档 03
7. Nginx 反代 API + 申请 HTTPS 证书；（方案B 同时配 `/static`）。 → 文档 03
8. 微信公众平台配 **服务器域名白名单**（request=API 域名，downloadFile=CDN/静态域名）。 → 文档 04
9. 用真实 AppID + 生产环境变量 **构建小程序**，上传体验版 → 提审 → 发布。 → 文档 04
10. 按**端到端验收清单**逐项点检（登录/播放/收藏/会员/拉新），全绿即上线完成。 → 文档 04

> （可选）需要运营/内容管理后台的，参文档 05，可在第 7 步（Nginx/证书）后并行部署。
