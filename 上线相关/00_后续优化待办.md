## 二、待办优化项（按性价比排序）

### P1 · 大索引「按需加载 + 本地缓存」（收益大、纯前端）
**现状**：`_search_story.json`(1.27MB)、`_search_song.json`(1.84MB) 等大索引，进相关页面才拉；gzip 后约 258KB，但每次冷启动仍重新下载。
**做法**：
1. 确认加载时机：确保大搜索索引**只在进入搜索/对应 Tab 时**加载，不在 App 启动首屏加载（`indexLoader.ts` / `freePool.ts`）。
2. 加本地缓存：用 `Taro.setStorage` 缓存索引 JSON，带一个**版本号/日期键**（索引 `generated_at` 字段可直接用作版本）。命中缓存直接读本地→二次打开秒出；版本变了才重新拉。
**风险**：低。注意 weapp 单 key 存储上限（1MB/key、总 10MB），大索引需压缩存或分片存，或只缓存「解析后的精简结构」。

### P2 · 小程序分包 subPackages（首开更快）
**现状**：主包 dist ~1.5MB（未分包，`app.config.ts` 无 `subPackages`），在 2MB 上限内但未来页面变多会顶格。
**做法**：把非首屏页面（播放器 `*/player`、成长 `growth/*`、会员 `common/member`、家长 `parent/*`）拆到分包，首次打开只下主包，其余按需下载。
**风险**：中。需回归测试所有页面跳转路径、`tabBar` 页必须留在主包、分包间跳转用绝对路径。改完走完整生效链（build→重载→逐页截图）。

### P3 · `useDidShow` 重复请求节流（减少来回请求）
**现状**：部分页面每次 `useDidShow` 都 `refreshProfile()` 等，切页频繁时重复拉取。
**做法**：加轻量节流（如 30s 内不重复拉）或在 store 里做时间戳去抖。
**风险**：低。注意别把「需要实时刷新的场景」（如支付回来、退出登录）也误挡。

### P4 · 静态缓存头延长（配合 CDN，二次打开更快）
**现状**：`/static` 已 `maxAge=1 天`。
**做法**：内容文件名基本不变，可延长到 7~30 天甚至 `immutable`；索引 JSON 保持短缓存或用版本号。**方案 A（CDN）下在 CDN 控制台配缓存规则更合适**（见文档 03）。
**风险**：低。索引类别设长缓存否则更新不及时。

### P5 · 内容瘦身（降存储/降 CDN 成本，非必须）
**现状**：`audio/` 约 352GB、`generated_stories/` 约 93GB，两者主题目录镜像，可能有重复/中间产物（如 `audio/_dedup`、`redub_run.log`）。
**做法**：上线前梳理「索引实际引用到的文件集合」，只部署被引用的音频，剔除中间产物；可显著降低 CDN 存储与流量成本。
**风险**：中。必须先用脚本比对索引引用与磁盘文件，验证无缺漏再删；建议先在 COS 上做，别动本地母本。

## 三、不建议现在做（记录备查）
- **webp 全量替换封面**：微信模拟器不解码 webp（真机可），项目规范倾向 jpg/png；现有封面 `webp` 属性 + 真机可用，够用，不折腾。
- **HTTP/2 Server Push / 预加载下一首音频**：收益不稳定，等有真实用户数据再评估。
